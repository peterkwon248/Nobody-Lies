## 0. 선행 — PLAYTEST.md 신설 (코드보다 먼저 · 5분)

`docs/PLAYTEST.md` 를 만들고 이 지시서의 배경 자체를 첫 데이터로 적는다:

```
2026-08-05 · 채널: 사용자 구두 보고
- 상황판: 모바일에서 사용 불가 수준. 테스터 중 제거 의견 있음 (사용자 동의)
- 평면도: 모바일에서 뭉개짐
- 프롤로그 카드: 데스크톱에서 모바일 크기로 작게 나옴
```

**형식을 설계하지 마라** — 날짜 · 채널 · 한 줄이면 충분하다. 형식화는 데이터가
쌓인 뒤의 일이고, **형식부터 짓기 시작하면 그것이 코드 작업의 우회 복귀다.**

## 1. 상황판 제거 — ★ 지우기 전에 잰다 ★

**측정 (삭제보다 먼저)**: 상황판이 다른 채널에 없는 정보를 나르는가.

```
① 상황판 컴포넌트가 읽는 데이터 소스를 전부 나열한다
② 각 소스가 다른 채널(격자·물증 카드·확보 단어·보고서·서술문)에도
   닿는지 대조한다 — matrix.ts 의 채널 행렬이 이 대조의 출처다
③ 전부 겹친다  → 상황판은 렌더링이다. 삭제가 공짜다 (정보 이중화 원칙)
   유일 정보가 있다 → 그것만 다른 채널로 옮기고 나서 지운다.
   옮길 곳이 애매하면 목록으로 보고하고 멈춘다 — 저작 판단이다
```

삭제 시:

- 컴포넌트 + 진입 UI(버튼·탭) + 관련 상태 키를 **같이** 지운다 — 죽은 코드를
  남기지 마라 (`PL` 상수 · `guiltyUnder` 의 계보).
- `matrix.ts` 에 상황판 채널 행이 있으면 같이 정리한다 — 역방향 검사가 있으니
  표식 문자열을 정확히 (08-04에 밟은 함정).
- 상황판이 `inShipGate` 대상 채널이었다면 게이트 숫자가 움직인다 — **움직인
  숫자를 커밋 메시지에 전후로 적는다.**

## 2. 흐르는 화면 — CSS 만으로 (코드 분기 금지)

프롤로그 인터루드 · 진술 카드 · 서술문 · 보고서가 대상이다.

- 고정 px 폭/글자를 `clamp()` · `rem` · `max-width` 로 바꾼다. **한 수리가
  양방향을 고친다** — 데스크톱에서 쪼그라드는 것과 모바일에서 넘치는 것은
  같은 병(고정폭)의 반대 증상이다.
- **JS 로 `isMobile` 분기를 만들지 마라.** 뷰포트 분기 코드가 두 벌이 되는 순간
  「같은 판정이 두 벌 있으면 갈라진다」가 UI 에서 재현된다.
- `App.jsx` 가 5,160줄 단일 클래스다 — **이 작업에서 구조 리팩터링을 시작하지
  마라.** 스타일 수리만. 리팩터링은 별도 결정이다.

## 3. 공간 화면 — 평면도만 전용 동작

평면도(도면·격자류 2차원 정보)는 축소로 해결되지 않는다.

- 뭉개짐의 답은 「작게 잘 그리기」가 아니라 **「필요할 때 크게 보여주기」**다:
  좁은 화면에서는 **축소 미리보기 + 탭하면 전체화면 오버레이 + 핀치줌/드래그.**
- 전체화면 구현은 **라이브러리를 들이지 말고 CSS transform 으로** — 외부 의존
  추가는 이 작업의 범위 밖이다.
- **데스크톱 동작은 바꾸지 않는다.**

## 4. 검증 — 이 저장소의 규칙 그대로

- 게이트 15단 exit 0 — UI 작업이지만 엔진을 건드리는 순간(채널 행렬 등) 전체가 돈다.
- **뷰포트 실측** — 최소 3폭에서 스크린샷: 375px(모바일) · 768px(태블릿) ·
  1440px(데스크톱). 프롤로그 카드가 1440 에서 콘텐츠 폭을 실제로 쓰는지,
  평면도가 375 에서 탭-확대가 뜨는지.
- **심어서 확인** — 상황판 삭제 후 그 데이터 소스를 참조하는 코드가 0인지
  grep 으로. 남아 있으면 죽은 참조다.
- 커밋은 단계별로 가른다: ⓪ PLAYTEST ① 측정+제거 ② clamp ③ 평면도.
  **①의 측정 결과(겹침/유일 정보 목록)는 커밋 메시지에 남긴다.**

  목록으로 모아 보고. 하나씩 임기응변으로 고치지 마라

## 0. 산정 근거 — `npm run space-audit`

```
세계 = 범인 후보 5 × 범인의 진실 격자(장소^슬롯) × 죽인 칸(사망 구간 칸 수)

mountain-lodge        5 × 5^4 × 1 =   3,125
practice-room         5 × 7^4 × 1 =  12,005
생성 40건 (전건 동일)  5 × 7^3 × 1 =   1,715
최악 손잡이(칸3·장8)   5 × 7^5 × 3 = 252,105   · 25ms. 여전히 초 미만
```

> ⛳ **`× 죽인 칸` 은 2026-08-04에 붙었다** — `World.murderCell` 신설(§2).
> **커밋 4건과 생성 40건은 전부 창이 1칸이라 세계 수가 안 변했다.**
> 손잡이를 `deathCells 3` 으로 올린 사건만 ×3 이 된다.

> ⛳ **인용의 내력** (2026-08-04). v1 스펙은 `space-audit.ts` 를 *"(이미 있음)"* 이라고
> 적었는데 **우리 트리에는 없었다** — 상대의 분석용 클론에만 있었다. 그래서 위 숫자를
> **인용을 못 믿고 독립으로 다시 재서** 확인했고 전건 일치했다. 그 뒤에 파일을 들였다.
> **순서가 중요하다** — 숫자가 맞아서 인용을 봐준 것이 아니라, 인용이 안 맞아서 다시
> 쟀더니 맞았다. ⑤검열관의 **ⓐ(인용 대조)** 가 설계된 그대로 작동한 자리다.
> 지금은 파일이 저장소에 있으므로 **인용이 참이다.**

- 무고한 넷의 격자는 가설 변수가 **아니다** — 「무고한 사람은 거짓말하지 않는다」가
  규칙이므로 그들의 `claim`(없으면 `presence`)이 곧 진실로 고정된다.
  ★ **그 규칙이 말이 아니라 코드라서 성립한다** — `verifier.ts` §7.5 가 무고한 자의
  `claim ≠ presence` 를 **오류**로 막는다. 경고였으면 산정 전체가 무너진다.
  실측: 규칙이 없으면 **10¹³~10²¹** (`space-audit` 의 마지막 표).
- 제출 공간(공란 후보의 곱, 최대 10¹⁵)은 **열거하지 않는다** — 공란의 답은
  세계의 함수다. 모호 = 일관된 두 세계가 **서로 다른 답안 벡터**를 낼 때뿐이다.
- 부분 정보(조사 부분집합 2^A)도 **열거하지 않는다** — 진실 세계는 모든 물증과
  일관이므로 어떤 부분집합에서도 일관 집합에 포함되고, 물증이 늘수록 집합은
  단조 감소한다. 검사할 것은 ① 전체 정보 유일성 ② 예산 내 오라클 경로의 장별
  확정 가능성 둘뿐이다.
- **외부 솔버(clingo/Z3) 불필요.** 1단계 실측: 최악 손잡이 84,035 세계가 **25ms**,
  커밋 4건 + 생성 40건 전건이 **130ms**.

## 2. 세계(가설)의 정의

```ts
type World = {
  culprit: PersonId                      // 5 후보
  culpritTruth: PresenceCell[]           // 범인의 진실 격자 — 장소^슬롯
  exitSlot?: SlotId                      // 트릭이 exit 을 가지면: 사망 구간 칸 중 하나
}
```

- 무고한 넷의 진실 = 그들의 `claim ?? presence`. **세계에 넣지 않는다.**
- `addClaims` 의 진위: 무고한 자의 추가 진술은 참으로 고정, 범인의 것은
  `culpritTruth` 와 대조해 참/거짓이 **도출**된다. 가설 변수가 아니다.
- 트릭 아키타입은 사건 데이터다 — 가설이 아니라 **일관성 제약의 출처**다.

## 3. 관측 표면의 정의 (★ 정보 이중화 원칙의 성문화 자리 ★)

솔버가 읽는 것은 **구조화 채널 전부이고 산문은 0** 이다:

```
브리핑        incident.kind · scene · body_state/scene_state 의 구조 필드 · seed_terms
격자          people[].claim (없으면 presence) · slots · locations(atLodge)
물증          evidence[] (id · foundAt · yieldsTerms · isStaging · atScene)
조사          actions[] (gives · cost · availableAfter · target · pair · yield)
사실          facts[] (kind · subject · revealedBy · requires · availableAfter)
트릭          trick (types · illusions.madeBy/brokenBy · exit.brokenBy · flaw.plantedIn)
도면          floorPlan.walks[].min (from·to 가 있는 것만)
공란          chapters[].blanks (label · answer · candidates · candidatePool)
```

- ⚠ 산문(진술 paragraphs · 프롤로그 · 결과문 body · 인터루드)은 **읽지 않는다.**
  이것이 정보 이중화 원칙이다: 솔버가 산문 없이 유일해에 도달하면, 풀이에 필요한
  모든 정보가 구조에 있다는 것이 **증명**되고, 산문 결함은 정의상 플레이어를
  막을 수 없게 된다. 손저작 사건이 여기서 빨개지면 그건 솔버의 결함이 아니라
  **산문에만 사는 결정적 정보의 발견**이다 — 구조 채널로 옮겨 적는 것이 수리다.

## 4. 일관성 함수 — `consistent(c, w, ctx)`

**이 함수가 스펙의 본체다. 조항 하나가 빠지면 증명이 조용히 약해진다.**

```
C1  범인 거짓 요건   ✅ 1단계  w.culpritTruth ≠ 진술 인 칸이 사망 구간에 ≥ 1  (§7.5(iv) 뒤집기)
C2  기회의 물리      ✅ 1단계  사망 구간 중 현장 접근 가능한 자리에 있다
C3  유죄 유일성      ✅ 1단계  전체 정보에서 유죄가 서는 사람이 w.culprit 하나뿐
C4  무고 배제        ✅ 1단계  나머지 넷은 셋 중 하나가 끝내 안 선다
C5  트릭 계약        🔨 2단계  ARCHETYPES — requiresExit · requiresIllusion
C6  인상 파괴 가능   🔨 2단계  모든 illusion.brokenBy 가 조사로 도달 가능
C7  물증 귀속        ⛔ 적힌 대로는 못 짓는다 — 아래 §C7 결함
C8  허점 실재        🔨 2단계  trick.flaw.plantedIn 이 실재하고 도달 가능
C9  공란 도출        ✅ 3단계  murderCell 도입으로 미결 30건 → 0
```

### ⛔ C7 이 가리키는 필드가 장소 참조가 아니다 (2026-08-04 실측)

스펙은 *"그 물증의 `foundAt` **장소**에 범인이 실제로 간 칸이 있다"* 라고 적었다.
**`foundAt` 은 장소 참조가 아니다** — `Evidence.foundAt?: string` 이고 실물은
사람이 읽는 문구다:

```
mountain-lodge   e_briquette  foundAt="다인의 방 · 화로"     location id 는 main·room·annex·approach·home
gen-1            e_tool       foundAt="방"                  location id 는 hall·room·loc1…

전수 44건   foundAt 이 location id 인 것   0 / 51
            foundAt 자체가 없는 물증        661
```

**타입이 `string` 이라 컴파일러가 안 잡는다.** 초안을 걸어보니 **진짜 세계까지 지웠다**
(44건 전부 `unsat`) — §4 가 경고한 「더 지우는 오차 = 거짓 유일」의 실례다.

> ★ **그리고 내 계측 도구가 그것을 `unique` 로 인쇄했다** ★ 살아남은 세계가 0인데
> 「답안 벡터 ≤ 1」을 유일로 셌다. *"39건이 unique 가 됐다"* 가 실은 *"39건이 죽었다"*
> 였다. **이 저장소가 여덟 번 잡은 「장부가 자기를 틀리게 말한다」의 아홉 번째다.**

**C7 을 지으려면 먼저 결정이 필요하다** — 물증에 장소 참조 필드를 새로 두느냐
(`foundAtLoc?: LocationId`), 아니면 C7 을 버리느냐. **저작 결정이라 묻는다.**

- `deriveFacts` · `deriveTerms` · `guiltTable` · `availableActions` 는 **재사용한다.**
  같은 판정 로직이 두 벌 있으면 반드시 갈라진다.
- C2 의 「왕복 가능」은 **보수적으로** 판정한다. `Slot` 에 시간 폭이 없어(id·label·
  isWindow 뿐) `walks.min` 으로 계산할 수 없으므로 **부지 안이면 전부 가능**으로 둔다.
  ★ **오차의 방향** ★ 덜 지우면 「모호」(가짜 빨간불 = 사람이 본다), 더 지우면
  **「거짓 유일」**(초록불이 거짓말한다 = 최악). **의심스러우면 덜 지운다.**

### ⚠ 1단계 실측이 드러낸 것 둘 (2026-08-04)

**ⓐ C3·C4 는 전체 정보에서 동어반복이다 — 단, `verify` 초록의 하류에서만.**
`guiltTable` 은 `facts[].subject` 를 세므로 **격자와 무관**하고, `verifier.ts:239-243`
이 이미 「유죄 정확히 1명 ∧ `c.culprit` 와 일치」를 **오류로** 강제한다.
그래서 위 표의 「범인 후보 1」은 **발견이 아니라 보장**이다.

> ⛔ **「변별력 0이니 지우자」는 함정이다** (사용자 정정 · 2026-08-04).
> 잉여인 것은 **`verify` 를 이미 통과한 사건에서만**이다. 세 자리에서는 **C3·C4 가
> `unsat` 을 무는 유일한 조항**이 된다:
> ```
> mute-check 의 뮤테이션 사건    일부러 깨진 상태 — verify 의 그 검사가 무력화된 판
> 손저작 초안                    verify 를 아직 안 돌린 단계
> solve-check ③ 의 심은 판       「심은 것이 안 물리면 실패」의 대상
> ```
> **죽은 조항이 아니라 「초록의 하류에서만 잉여인」 조항이다.** 지우면 위 셋이
> 조용히 통과한다 — 이 저장소가 여덟 번 잡은 부류 그대로다.

> **「누가 범인인가」의 변별은 4단계 `curve` 에서 나온다** — 예산 안에서 그 사실
> 집합에 닿는가. 전체 정보에서는 언제나 1이다. **둘을 같은 것으로 세면 안 된다.**
> ⛳ **4단계가 끝나면 §5 의 `curve` 설명을 고친다** — 지금 「난이도 부산물」이라고
> 적혀 있는데 실은 **범인 축 변별의 본체**다. (사용자 지시 · 2026-08-04)

**ⓑ C1·C2 는 사망 구간 칸만 묶는다.** 나머지 슬롯은 **완전히 자유**다(`L^(S-1)`).
실측 — `closing-theater` 는 남은 245 세계가 전부 「사망 구간 칸 5가지 × 비-사망구간
7² = 245」다. 그래서 **비-사망구간을 묻는 시각 공란 43개**(전체 128 중)가
3단계에서 `ambiguous` 로 뜰 후보다.

> ⚠ **후보이지 확정이 아니다** — 무고한 넷의 격자는 고정이므로 그들에 관한 공란은
> 안 갈린다. **범인의 자유 칸을 묻는 것만** 갈린다. 3단계가 가른다.

## 5. 판정 — `solve(c: Case): SolveResult`

```ts
type SolveResult = {
  worlds: number
  verdict: 'unique' | 'ambiguous' | 'unsat' | 'undecidable'
  answerVectors: number
  blankVerdicts: Record<string, 'discriminated' | 'vacuous'>  // §6 관할 — 솔버가 계산
  witnesses?: World[]
  curve?: { step: number; worlds: number }[]
}
```

```
unsat        일관 세계 0 — 사건 데이터 자체가 규칙과 모순 (verify 가 놓친 것)
unique       답안 벡터 1 — ★ 출시 조건 ★  (세계가 여럿이어도 답이 같으면 유일이다)
             답안 벡터는 discriminated 공란만으로 구성한다 — vacuous 는 §6 관할이 다르다
ambiguous    답안 벡터 ≥ 2 — 성실한 플레이어가 틀릴 수 있다. witnesses 를 인쇄한다
undecidable  C9 실패 — 솔버 스펙의 구멍. 삼키지 말고 그대로 보고
```

- ★ **자기 검사 1호** ★ 진짜 세계(데이터의 `presence` 그대로)가 일관 집합에 **반드시
  포함**돼야 한다. 안 되면 일관성 함수가 고장난 것이다.
  ✅ **1단계에서 44건 + 최악 손잡이 전건 통과.**
- `curve` 는 `simulate()` 의 경로를 따라 물증을 누적하며 세계 수를 찍는다.
  마지막 점이 1이 아니면 **예산 내에서 유일해에 못 닿는다.**

  > 부산물」이라고 적혀 있는데 **실은 「범인 축 변별의 본체」**다. 3단계 실측이

  > 범인을 고정해 전부 `vacuous` 로 떨어진다. 전체 정보에서는 「누가」가 언제나
  > 하나이므로 **변별은 「예산 안에서 거기 닿는가」에서만 나온다.**

## 6. 교차 검증 — `proof.ts` 와의 관계 (v2)

> v1 은 「`proof.ts` 를 설명 생성기로 강등」이었다. 공란 702개를 답의 출처로 갈라
> 재서 **철회**했다: **263개(37.5% · 확보 단어류)는 모든 세계에서 답이 같아** 솔버가
> 변별 없이 `unique` 를 돌려주고, 그 자리를 무는 것은 `proof`/`weakBlanks` 뿐이다.
> 강등하면 37.5%가 무검사가 된다 — 「초록인데 아무것도 안 물고 있다」의 재생산.

**공란별 관할은 솔버가 스스로 계산한다 (목록 유지 금지 · `inShipGate` 선례):**

```
discriminated   일관 세계들 사이에서 answerOf 가 갈린다   → 솔버가 정본
vacuous         모든 일관 세계에서 answerOf 가 같다        → 솔버 판정 없음 · proof 가 정본
```

경계를 손으로 적으면 새 공란 유형이 생길 때마다 어긋난다. 계산하면 자동으로
옳은 쪽에 떨어진다.

**교차표:**

```
discriminated ∧ 솔버 unique ∧ 사슬 섬      정상 — 사슬을 설명으로 인쇄
discriminated ∧ 솔버 unique ∧ 사슬 안 섬   정상 — 규칙표의 부분성 (경고 유지)
discriminated ∧ 솔버 ambiguous ∧ 사슬 섬   ★ 둘 중 하나 고장 ★ — exit 1 · 근거 나란히
vacuous ∧ 사슬 또는 weakBlanks 가 문다      정상 — proof 관할
vacuous ∧ 아무것도 안 문다                 ★ 무검사 공란 ★ — exit 1
솔버 unsat                                 exit 1 무조건
```

**넷째·다섯째 줄이 v1 에 없던 것**이고, 다섯째가 강등이 만들 뻔한 구멍을 명시적으로 센다.
**discriminated 에서는 솔버가, vacuous 에서는 proof 가 정본이다** — 솔버의 `unique` 는
vacuous 공란에 대해 **판정이 아니다**(정보 0 기여).

## 7. `solve-check` 게이트

```
① 커밋 4건 — closing-theater 는 프롤로그 불일치를 일부러 남긴 사건이지만
   솔버는 산문을 안 읽으므로 통과해야 정상이다. 통과 못 하면 구조 결함 발견.
② 생성 40건 (gen-check 표본과 같은 시드) — 전건 unique
③ 뮤테이션 — ★ 심은 것이 안 물리면 실패 ★ (clue-check ② 의 선례. 이것이 없으면
   ①②는 솔버가 죽어 있어도 초록이다):
     · 무고한 한 명의 claim 을 범인 동선과 같게 → ambiguous 가 떠야 한다
     · illusion.brokenBy 를 비움 → unsat 또는 curve 미도달이 떠야 한다
     · 범인의 창 거짓말 제거 → unsat 이 떠야 한다
④ 진짜 세계 포함 검사 (자기 검사 1호) — 전건에서 확인
```

- `mute-check` 의 뮤테이션 목록에도 솔버 배선 절단을 추가한다.

## 8. 착수 순서

> ⛳ **순서를 2↔3 바꿨다** (2026-08-04 · 사용자 확정). v1·v2 는 `2 → 3 → 4` 였다.

```
0  ✅ availableActions · simulate export (+ simulate 에 trace 추가) · space-audit 들이기
1  ✅ World 열거기 + C1~C4 — 실측 완료 (위 §4 ⓐⓑ)
3  🔨 answerOf + 답안 벡터 + discriminated/vacuous 판정   ← ★ 다음 ★
2     C5~C8 — **3단계가 남긴 잠정 모호의 해소기**
4     curve (simulate.trace 접목) — ★ 「누가 범인인가」의 변별이 여기서 나온다
5     solve-check + 뮤테이션 3종
6     proof.ts 교차 검증 배선 (§6 교차표)
7     커밋 4건 실측 — 빨간불이 나오면 그것이 첫 수확이다
```

### 왜 3이 2보다 먼저인가 — **단조성이 초록불을 못 거짓말하게 한다**

```
지금 세계 집합은 덜 지워진 상태다 (C1~C4 만).
  이 큰 집합에서 답안 벡터가 이미 1  →  C5~C8 로 집합이 줄어도 벡터는 새로 못 생긴다
                                      →  ★ 지금의 unique 는 최종 판정이다 ★
  ambiguous                          →  잠정. C5~C8 이 해소할 수 있다
```

**§4 의 「의심스러우면 덜 지운다」가 순서 자체에 박힌다** — 이 차례로 가면 초록불이
거짓말할 수 없고, 빨간불만 잠정이다. 반대 순서(2 먼저)는 세계를 더 지운 뒤에 처음
판정하므로 **거짓 유일**의 위험을 앞에 놓는다.

**그래서 2단계의 지위가 바뀐다** — 「세계를 더 지우는 조항」이 아니라
**「3단계가 남긴 잠정 모호를 해소하는 기계」**다. 무엇을 해소해야 하는지 안 뒤에
지으면 지우는 방향의 위험이 최소가 된다. 새 기계도 0이다 — `answerOf` 는 이미 열거된
집합 위의 함수 적용이고, `curve` 만 「물증 부분집합에 조건화된 일관성」이라는 **새 평가
모드**를 요구한다. 그래서 `curve` 가 마지막이다.

## 9. 하지 않는 것

- 산문을 읽지 않는다. 산문 검증은 검열관(⑤)의 몫이고 이 모듈의 범위 밖이다.
- 부분집합 2^A 를 열거하지 않는다 (§0 단조성).
- 제출 공간의 곱을 열거하지 않는다 (§0 답안 벡터).
- 재미·난이도 체감을 판정하지 않는다. `curve` 는 **측정치**지 합격선이 아니다 —
  합격선은 테스터 데이터 이후의 저작 판단이다.
- 런타임 LLM 0. 이 모듈에 LLM 은 어떤 형태로도 없다.

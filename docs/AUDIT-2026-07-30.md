# 1. 엔진 — 잘 돼 있다

## 본보기로 삼을 것 (건드리지 말 것)

**`Person.claim?`** 이 이 저장소 최고의 설계다.

```ts
claim?: PresenceCell[]   // 없으면 진술 = presence
```

「무고한 자는 거짓말하지 않는다」가 **구조적으로 못 깨진다.** 진술을 손으로 안
쓰므로 실수로 거짓이 섞일 수 없다. 주석이 그 이유를 정확히 적어놨다:
*"손으로 쓰지 않으므로 실수로 거짓이 섞일 수 없다."*

**이것이 ①이 가야 할 방향의 완성형이다.** 검사로 잡는 게 아니라 틀릴 자리가 없다.

그 밖에 — `ArchetypeContract`(트릭이 이름표가 아니라 계약) · `Particle` 쌍 ·
`DOMAIN_OF` 도출 · `flaw.plantedIn` · `report` 의 공란 1회 강제. 전부 옳다.

## 🔴 1-A. `Fact.content: string` — 오늘 버그의 타입 층 뿌리

```ts
kind: FactKind      // 구조. 기계가 읽는다
subject: PersonId   // 구조. 기계가 읽는다
content: string     // ← 플레이어가 읽는 문장. 아무것과도 안 이어져 있다
```

`kind: no_opportunity` · `subject: p2` 는 구조인데 **`content` 만 자유 문자열**이라
`presence` 격자와 대조할 방법이 **타입 층에 없다.** 그래서
`'아침에 함께 도착했다'` 가 게이트 초록으로 전건에 실렸다.

**오늘 고친 것은 값이지 구조가 아니다.** 다음 세계에서 또 거짓이 될 수 있다.

같은 꼴이 넷 더 있다 — 전부 플레이어가 읽고 전부 대조 불가:

```
Fact.content          Evidence.description      Evidence.record
Chapter.opening       Action.result.body
```

**고치는 법** — 문장 대신 근거를 쓰고 문구는 도출한다:

```ts
basis: { kind: 'together'; slot: SlotId; at: LocationId }
// content 는 basis 에서 만든다 → 검증기가 presence 와 직접 대조한다
```

## 🔴 1-B. `Text`(2개국어)가 절반에만 붙어 있다

```
Text 다 (8)      claimSummary · statement.paragraphs · terms.source/note ·
                result.title/body · ActionClue.text · RelationGraph.label
string 이다 (15+) Person.name · job · Slot.label · Location.label · Fact.content ·
                Evidence.description · record · Action.label · Chapter.title ·
                opening · rooms[].label · doors.label · fixtures.label ·
                Reveal.narration · incident.description
```

35행 주석: *"어휘가 고정이라 번역이 싸다 — 템플릿 20개를 번역하면 사건 1000개가
번역된다."* **그런데 화면에 보이는 문자열의 절반은 번역을 담을 자리가 없다.**

「빌드타임 LLM 4곳」 중 하나가 **번역**인데 **그 슬롯이 지금 물리적으로 불가능하다.**
이미 발화한 적도 있다 — *"영문이 버려지고 있었다 — `applyCase` 가 `ko` 만 덮어써서
엔진이 써둔 `en` 이 통째로 죽고"*.

> **결정 필요**: 번역을 할 것인가. 한다면 `Text` 를 전 필드에 깔아야 하고 그건
> 큰 변경이다. 안 할 거면 **「4곳」 목록에서 번역을 빼야 한다** — 지금은 예산만
> 차지하고 있다.

# 2. 검사층 — 촘촘한데 **한 부류를 통째로 못 본다**

오류 90 · 경고 23. 전량을 뽑아 분류했다.

```
✅ 참조 무결성   모든 id 가 실재하나 (슬롯·장소·인물·조사·물증·고정물·도식)
✅ 논리         풀리나 · 유일한가 · 예산 안인가 · 교착 없나 · 아키타입 계약
✅ 기하         방 겹침 · 건물 밖 · 문으로 못 닿는 방 (§9-3i)
✅ 누설         산문이 「확보 단어」를 미리 말하나
❌ 모순         산문이 데이터와 어긋나나                    ← 검사 0개
```

## 🔴 2-A. 산문 검사 넷이 전부 **부분 문자열 검색**이다

`verifier.ts:1144~1186` 전문을 읽었다. (a)(b)(c)(d) 넷 다 같은 모양이다:

```js
const ghost = words.filter((w) => !seeded.has(w) && !own.has(w) && text.includes(w))
```

**「확보 단어 목록의 낱말이 이 문장에 들어 있나」**를 볼 뿐이다. 문장이 **참인지는
한 번도 묻지 않는다.**

그래서 오늘 나온 둘을 **구조적으로 못 잡는다** — 둘 다 확보 단어를 안 쓴다:

```
f_no_p2.content  '아침에 함께 도착했다'   vs  p2.presence [t0:hall, t1:approach, t2:hall]
prologue[1]      '다음 날 아침'          vs  slots.t2.label '자정을 조금 넘긴 무렵'
```

**첫째는 기계로 잡을 수 있다** — `kind`·`subject`·`presence` 가 전부 구조다.
`content` 만 산문이라 못 잡는 것이므로 **①(도출)이 이것을 없앤다.**

**둘째는 기계로 반쯤만 잡힌다** — 「프롤로그의 시각 표현이 `slots[].label` 집합에
있나」는 검사 가능하다(완벽하진 않다). 나머지가 ⑤검열관 몫이고, **오늘 그 실물이
`closing-theater.yaml` 에 커밋돼 있다.**

# 4. 제품 — UGC 의 급소

사건이 앱에 들어오는 길은 **딱 둘**이다 (`main.jsx:159`):

```
1. fetch('/cases/<id>.json')              빌드에 들어간 정적 파일
2. localStorage 'nobody-lies:generated'   ?case=local:<id>
```

**들여오기가 없다.** `<input type=file>` · `FileReader` · YAML 붙여넣기 **전부 0건**
(전수 grep). `exportOne`(YAML 다운로드)은 있다. **한 쌍의 반쪽이 없다.**

```
유저가 만든다 → localStorage → YAML 내려받기 → ??? 돌아갈 길이 없다
```

- 자기 브라우저에서 **플레이는 된다**
- **남에게 줄 수 없다** — 받은 사람이 열 방법이 없다
- **브라우저를 갈면 사라진다** — 내려받은 YAML 도 못 되돌린다
- 남에게 닿는 유일한 길: 개발자가 `engine/cases/` 에 커밋하고 재빌드

`Generator.jsx:672` 가 이미 그 아픔을 적어놨다 — *"산문을 입힌 사건은 저작물인데
`localStorage` 에만 살고 작업 기계가 넷이다. 안 꺼내고 브라우저를 갈면 못 되찾는다."*

**개발자의 불편으로 적힌 것이, UGC 가 상품이면 상품 전체의 구멍이다.**

## 고치는 값은 싸다

**들여오기 하나**면 파일로 주고받는 UGC 가 성립한다. 서버가 필요 없고
§8(API 안 씀)·§4(AI 없이 동작)를 다 지킨다. 개발자의 네 기계 문제도 같이 풀린다.

그 너머(링크 공유·사건 목록·발견)는 서버가 필요하고 별개 결정이다.

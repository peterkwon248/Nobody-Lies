## 절대 규칙 — 새 화면·기능마다 확인할 것

> **게임이 플레이어의 판단에 대해 하는 말은 최종 채점 하나뿐이다. 그 전까지 완전한 침묵.**

이 게임의 상품은 "내가 알아냈다"는 감각이다. 아래를 위반하면 상품이 사라진다.

| 금지 | |
|---|---|
| 실시간 채점 | 장을 완성해도 정답 여부를 알리지 않는다 |
| 모순 경고 | "확보한 물증과 어긋납니다" 없음 |
| 게임이 하는 텍스트 강조 | 볼드·하이라이트·색칠 |
| 유용도 시각 구분 | 결정적 단서와 레드 헤링이 완전히 동일하게 생겨야 함 |
| 프로필의 유죄 판정 | 사실만. `기회 있음 ✓` 금지 |
| 조사 추천·힌트 | 없음 |
| 자동 분석 일체 | 모순 탐지·타임라인 해석 등 |

**이 규칙은 개발 중 일곱 차례 다른 형태로 재발했다** (배너 → 진술 볼드 → 프로필 판정 → 분석 보조 토글 → 모순 경고 → 물증 카드 `뜻` 필드 → 격자 자동 추출). 전부 "친절한 UI의 기본값"에서 나온다. 보통 앱은 중요한 것을 강조해주는 게 미덕이지만 이 게임에서 그것은 정답 누설이다.

부수 규칙 둘:
- **한 번 보여주고 사라지는 텍스트는 버그다.** 토스트는 "어디에 새 것이 생겼다" 신호만. 내용은 해당 화면에 영구히.
- **런타임 LLM은 0이다.** 예외 없음. 빌드 타임 4곳만(진술 산문 / 프롤로그 / 번역 / UGC 누설 검사), 결과는 파일에 고정.

## ⛏ 이식 규칙 — 코드를 쓰기 전에 마크업을 읽는다 (2026-07-25)

> **프로토타입에 이미 있는 화면은 옮기는 것이지 만드는 것이 아니다.**

```
1. 만들려는 화면이 프로토타입에 있는가?   grep 으로 마크업 위치를 찾는다
2. 있으면 → 읽고 옮긴다                    클래스·구조·인라인 스타일 그대로
3. 없으면 → 그때만 새로 그린다             그 사실을 커밋에 적는다
4. 검증에 육안 대조를 넣는다               빌드 통과는 이식 여부를 증명하지 않는다
5. 의도적으로 다르게 가면 근거를 대고 커밋에 적는다
6. 다르게 가기 전에 **낡은 것**과 **일부러 그렇게 쓴 것**을 가른다. 안 서면 묻는다
```

**6번은 태그라인 사건에서 나왔다.** 홈의 「모든 진술을 의심하라」를 설계 결함으로 보고
규칙 문장으로 바꿨는데 그것은 캐치프레이즈였다. 낡은 숫자(예산 5)를 안 옮기는 것은 맞지만
**작가가 의도해서 쓴 문구·연출·구성은 다르다.** 기술적으로 검증 가능한 것(숫자·데이터
정합)은 스스로 판단하고, **저작에 속하는 것은 묻는다.**

**2026-07-25에 같은 실수를 두 번 했다.** 홈·사건 상세에서 한 번(존재하지 않는 CSS 변수
`--text-primary` 를 쓰고 레이아웃을 새로 그림), 보고서·사이드바에서 또 한 번(문서 헤더
스트립·공란 칩·피커를 안 보고 발명). 둘 다 사람이 화면을 보고 지적해서야 드러났다.

원인은 게으름이 아니라 **주의 배분**이다. 두 번 다 새로 설계할 것(스키마·상태 구조)과
옮길 것(렌더)이 한 작업에 섞여 있었고, 설계 쪽에 집중하다 렌더를 "일단 돌게"로 처리했다.
**소스가 눈앞에 없으면 발명이 기본값이 된다** — 파일은 리포에 있었지만 그 줄을 읽지 않았고,
CSS 를 맨손으로 쓰는 것은 진척처럼 느껴져서 스스로 멈추지 않는다.

그리고 **기존 검증이 이것을 못 잡는다.** 빌드·타입체크·콘솔 에러·동작 확인은 화면이 전혀
다르게 생겨도 전부 통과한다. 그래서 4번이 규칙의 절반이다.

**이식에 DC 툴은 필요 없다.** 마크업은 전부 `prototype/추리게임.dc.html`(2946줄)에 있다 —
보고서는 185~270행, 사이드바는 75~135행, 상단 헤더는 140~168행, 우측 패널은 914~960행,
홈은 1066행부터. DC 툴이 필요한 것은 `DC-SYNC-CHANGESET.md` 반영 · 프로토타입에 **없는**
새 화면(장 인터루드) · 모바일 셋뿐이다.

**규모를 잘못 잡는 것도 같은 실수다.** 사이드바를 옮기고 "셸 완성"이라고 했는데,
`.main` 이 시작되는 140행에서 읽기를 멈춰서 상단 헤더와 우측 디테일 패널이 통째로
빠졌다. **뷰 하나가 아니라 그 뷰가 사는 껍데기 전체를 읽는다.**

**클래스 이름은 계약이다.** Vector 의 `.seg-toggle` 은 자식에 `.st`/`.st.active` 를
요구하는데 `on` 이라고 써서 스타일이 하나도 안 붙었다. 겉모습만 보고 "됐다" 하지 말고
디자인 시스템 CSS 에서 그 클래스가 무엇을 요구하는지 확인한다.

상세 조항은 `HANDOFF-TO-CODE.md` §8.1.

## 이식 전수 대조 (2026-07-25) — 45건이 빠져 있었다

**우측 패널 3건은 빙산의 일각이었다.** 이미 옮긴 7화면을 마크업 전 범위(73~1266행)와
한 줄씩 대조했더니 **누락 45 · 다름 17.** 전 과정은 `docs/PORT-AUDIT.md`.

### 감사가 방법이 아니라 청구서였다

사용자가 물었다 — *"그냥 프로토타입을 리액트로 그대로 구현하고 수정할 것만 고치면
되는 거 아니냐, 왜 일일이 대조하냐"*. **맞는 말이고 이유는 하나다.**

```
이식   원본 읽기 → 쓰기                        1패스   ← 빈 자리에 옮길 때
수리   원본 찾기 → 앱 찾기 → 차이 판정 → 고침   4패스 × 62건
```

앱엔 이미 7화면이 **원본을 안 읽고** 지어져 있었다. 그래서 이번 세션의 대부분은
이식이 아니라 **수리**였다. 감사 45건은 이전 세션들이 마크업을 안 읽은 값이다.

증거는 세션 안에 있다 — 앱에 **없던** 것을 통째로 옮긴 묶음(진술 화면·확보 단어
은행·평면도·조사 시스템)은 각각 한 번에 갔다. 느렸던 것은 전부 "이미 있는데 뭐가
다르지?"였다.

> **다음에 새 화면을 만들 때는 감사표를 쓰지 않는다.** 원본 구간 하나 읽고 컴포넌트
> 하나 쓴다. 대조가 필요하다는 것 자체가 이미 잘못 지었다는 뜻이다.

### 층을 가르지 않아서 사용자가 헷갈렸다

감사표가 45건을 평평하게 늘어놔서 `조사 예산 6`(엔진이 이김)과 `dashed 테두리`
(프로토타입이 이김)가 같은 표에 나란히 있었다. 축은 둘이다:

| 층 | 정본 |
|---|---|
| 클래스 · 구조 · 스타일 · **UI 문구** | **프로토타입** |
| 숫자 · 사실 · 어휘 · 판정 · **사건 산문** | **엔진** |

합의된 예외 8개(언어 전환 보류 · 모바일 보류 · 목록 모드 폐기 · 예산 5→6 ·

**나머지는 전부 원본이 정답이고 항목마다 판단하지 않는다.**

### 화면을 보고서야 잡은 것 셋

빌드·타입체크·검증기가 전부 통과한 상태에서 살아 있던 것들이다. **규칙 4번
(육안 대조)이 규칙의 절반인 이유.**

1. **`<style>` 블록이 통째로 안 옮겨져 있었다** — 원본 30~52행. `--g-*` 아홉을
   프로토타입이 48곳에서 쓰는데(공란 3상태 + 마킹 4색) 앱엔 0건. 토큰이 없으니
   값을 눈대중으로 채우고 있었다
2. **YAML flow mapping 쉼표** — `{ ko: 방문·창가 테이프, 화로에 연탄 }` 에서 쉼표가
   키 구분자로 먹혀 뒷부분이 **조용히 잘렸다.** 빌드도 검증기도 통과했다
3. **용의자 슬롯이 범인을 가리켰다** — 동기·기회·수단을 엔진 `Fact` 에서 도출했더니
   조사 0회에 **세라만 두 칸**이 차 있었다(무료 사실 2건, 나머지 넷 0건).
   다섯 중 하나만 채워진 카드가 곧 범인 표시다. 절대 규칙 「프로필의 유죄 판정 금지」에
   정확히 걸린다. → **조사로 얻은 사실만** 세도록 좁혔다.
   프로토타입이 슬롯을 조사 기록에서만 채운 것은 한계가 아니라 **설계였다**

### 발명이 필요하면 덜 옮긴 것이다

사이드바에 「조사」 항목을 만들어 붙였는데 **원본 nav 10항목에 없는 것**이었다.

`navMap` 은 「현장 평면도」가 아니라 **「현장」**, `invLogTitle` 은 **「조사 기록」**([도구]).

## 상황판이 탭 여럿이 됐다 (2026-07-27)

**상황판 자체가 그 장소가 된다.** 탭마다 바닥 도면 하나(평면도·도식·관계도)를 깔고
그 위에 서랍의 카드를 올린다. 탭은 스프레드시트 탭처럼 추가·이름·삭제.

```
pb 루트    화면 상태(휘발) + 공유(메모·타임라인)
pb.boards[]  탭마다 — placed·strings·groups·binds·pins·size·labels·backdrop
pb.active    활성 탭
```

**공유/탭별 기준은 「사건에 대한 기록인가, 이 추리에 대한 배치인가」다** — 메모는
사건에 대한 것이라 탭을 넘나들고, 배치는 그 추리에만 속한다(사용자 결정).

### 왜 싼 리팩터였나 — 구조 둘

| | |
|---|---|
| `PB_set(patch)` 이 **단일 관문** | 상황판의 모든 변경이 한 함수를 지난다. 여기서 콘텐츠 키는 활성 탭으로, 화면 키는 루트로 갈라 보내니 **93개 호출부가 안 바뀐다** |
| `get PB()` = **루트 + 활성 탭 병합 읽기** | `this.state.pb.` 86곳을 `this.PB.` 로 기계 치환했다. 병합이라 `s.placed`(콘텐츠)와 `s.pan`(화면)을 섞어 읽는 기존 코드가 **한 줄도 안 바뀐다.** `pb` 는 변경마다 새 객체이므로 identity 로 캐시한다 |

### 함정 셋 — 다 실측으로 잡혔다

- **드래그가 캔버스 패닝으로 샜다.** 고정 상태에서 `stopPropagation()` 없이 `return`
  했더니 pointerdown 이 캔버스로 넘어가 화면이 패닝됐다. 라벨·영역이 쓰는 관례가
  「고정돼 있어도 전파는 막는다」인데 그걸 안 따랐다. `PB_clampPan` 이 오른쪽을 40에서
  자르기 때문에 **「세로만 움직인다」로 보였다** — 판이 아니라 세계가 움직이고 있었다
- **시간대 전환을 안 가져왔다.** 평면도 마커는 `mapTime` 을 보는데 도면만 옮기고 그
  띠를 뺐다. `mapTime` 은 **순수 화면 상태**라 예산이 안 깎이고 아무것도 공개되지
  않는다 — 잠글 이유가 없었다. **「불활성」을 전부 잠금으로 만든 것이 과잉이었다**
- **`count: 0` 이 「평면도 0」으로 찍혔다.** 배지는 카드의 개수 자리인데 바닥에 0을
  넣었다. `textContent` 를 읽어서 잡았다 — DOM 검사가 시각 결함을 잡은 드문 경우

### 저장 마이그레이션 — 이번엔 감쌌다

`SAVE_VERSION 1 → 2`. v1 의 납작한 `pb` 를 **첫 탭으로 감싼다**. 「옛 저장은 조용히
버려진다」는 구조가 바뀔 때의 최후 수단이고, 감쌀 수 있는 변경에 쓸 것이 아니다.
v1 저장을 손으로 만들어 넣고 배치·라벨이 탭 0 으로 오는 것, 메모·타임라인이 루트에
남는 것을 확인했다.

> 한다 — 이번에 `buildSections()`(2180행)를 읽어서 잡았다.

**나머지 셋은 데이터가 없어서 못 옮긴다** — `cell.isNew`(격자 주장 공개) ·
고정물 아이콘 · 고정물 이름표. 셋 다 `NEXT-ACTION.md` §데이터 구멍에 적혔다.

`skip` 은 이유를 적는다. 이번에 늘어난 부류 하나 — **엔진과 원본의 데이터 형태가
달라 갈래 자체가 필요 없는 것**(`e.hasTarget`: 원본은 `actionLabel`+`targetLabel`
을 렌더에서 잇는데 엔진 `Action.label` 이 이미 「소지품 검사 · 오나경」이다).

**`npm run build` 에 걸었다.**

### 그리고 장부를 버렸다 (앱 교체 후)

장부가 있던 이유는 **손이식이 이름을 바꿨기 때문**이다(`l.clues` ↔ `cluesAt`) —
기계가 판정할 수 없어 사람이 적었다. 기계 변환은 이름을 그대로 쓰므로 그 전제가
사라졌다. 이제 **프로토타입과 `App.jsx` 를 직접 비교한다**:

```
sc-if  {{ x }}   ↔  {(V.x)?(<>…</>):null}
sc-for {{ x }}   ↔  arr(V.x).map(…)

전환 시점 308 대 308 · 어긋남 0
```

잡아주는 것 — 재export 가 분기를 빠뜨림 · 옛 마스터에서 온 export ·
프로토타입만 갱신되고 앱이 안 따라옴.

> ⚠ **초록불은 「덜 옮기지 않았다」이지 「맞게 옮겼다」가 아니다.** 장 머리글이
> 정확히 그렇게 빠져나갔다 — 두 갈래가 다 있는데 조건이 뒤바뀌어 있었다.

## 진행 저장 (2026-07-26) — 그리고 상태가 갈래로 나뉘었다

`route` 는 일부러 뺐다 — 새로고침하면 홈으로 나오고 「이어하기」로 돌아간다.

## 사건 파일 이관 (2026-07-26) — 절반쯤 왔다

층은 둘로 가른다 — **숫자·사실·어휘·사건 산문은 엔진, 클래스·구조·스타일·

앱 표가 상위집합이다(평면도 좌표·영문·역할 라벨은 엔진에 없다).

**엔진이 정본인 것** — 예산 · 프롤로그 · 인물 이름/나이/직업/주장요약 ·
진술 원문 5명 · 지문 · 공란 20의 답과 조사 · 장 제목 5 · 서사 문장틀 5 ·
확보 단어 출처/기록 · **관계 도식 라벨·게이트·위험표시** · **평면도 한국어 라벨 ·
도보 시간 · 별채 공개 게이트 · 축척 라벨 · 설비 좌표**(2026-07-27).

**아직 앱이 정본인 것** — `INV_ACTIONS`(모델이 다르다) · `TERM_MAP` ·
`CLUE_MAP` · `FLOOR_CLUES` · `REVEALS`·`CLAIM_REVEALS`(**모델이 다르다** —
`docs/NEXT-ACTION.md` 참조) · `COLLECTED_POOL` · `FIXTURES` 의 이름·아이콘 ·
평면도·관계 도식의 **좌표와 영문 라벨**.

### 관계 도식·평면도 이관 — 위치로 잇지 않는다 (2026-07-27)

`relation_graph` → `GRAPH_NODES`/`GRAPH_EDGES`/`GRAPH_EVIDENCE`,
`floor_plan` → `GEO`/`WALK`. 잇는 열쇠는 **노드가 `id`, 간선이 `(from,to)`,
창이 좌표 네 값, 동선이 `building`** 이다.

> ⚠ **엔진 `discoveries` 순서가 앱과 다르다** — 엔진 `a_yuri · a_ph_wy · a_annex ·
> a_sakura` ↔ 앱 `yuri · annex · sakura · wonyoung`. 순서로 이으면 「소지」와
> 「새벽 통화 확인」이 뒤바뀐다. `SECTIONS` 가 `s1,s3,s2` 였던 것과 같은 함정이다.

조사 id ↔ `logKey` 대응(`a_yuri` ↔ `belongings:yuri`)은 **일부러 안 썼다** — 그게
곧 `INV_ACTIONS` 충돌이고, `(from,to)` 네 쌍이 유일해서 없이도 이어진다.

화면으로 잡힌 것: `GRAPH_NODES` 의 피해자 `en` 이 `'Kim Chae-won'` 이었고,
`PEOPLE` 에 `victim` 이 없어서 **영문 모드에 그 값이 실제로 렌더되고 있었다.**
낡은 영문 이름 13건 중 1건이 이관으로 없어졌다. 평면도 `en`(`"Chae-won's room"`)은
**엔진에 영문이 없어서 그대로 남는다** — 로마자 표기가 결정되면 같이 받는다.

게이트는 조건만 데이터로 돌렸다(`revealed_after` → `GEO.buildings[].gate` →
`annexOn`). **어느 건물이 가려지는지는 필터 6곳이 아직 `'annex'` 이름으로 찾는다.**

### 옮기기 전에 값을 센다 — 세 번 값을 했다

| 발견 | 안 셌으면 |
|---|---|
| **앱 `SECTIONS` 배열이 `s1,s3,s2,s4,s5` 순** | `b1..b20` 순차로 이어서 **2장·3장 답이 뒤바뀜** |
| **엔진 네 문장이 쉼표에서 잘려 있음** | 앱의 온전한 문장이 잘린 것으로 **덮임** |
| 4장 조각 수 앱 7 vs 엔진 6 | **오진.** 인접 text 가 합쳐진 것 — 이어붙이면 같다 |

> **조각 수로 재면 오진이 난다.** 이어붙인 문장 + 공란 순서/답으로 재라.
> 개수가 어긋나면 그 장은 **아예 건드리지 않고** 경고만 남긴다 — 반쯤
> 덮어쓰는 것이 제일 나쁘다.

### YAML flow mapping 쉼표 절단 — 검사기를 만들었다

```yaml
note: { ko: 외상은 없고, 혈중 일산화탄소 농도가 높았다., en: "..." }
                     ↑ 여기서 끊긴다. 파서는 아무 말도 하지 않는다
```

`{ }` 안에서 쉼표는 항목 구분자다. 이 파일이 2026-07-25 에 같은 결함을 적어뒀는데
**네 건이 아직 살아 있었다**(`terms[].note.ko` — 일산화탄소 중독 · 유서 ·
별채 대포폰 · 영수증). 검증기는 참조 무결성만 보지 문장이 잘렸는지는 모른다.
`npm run yaml-check` 를 만들어 빌드에 걸었다 (음성 테스트 확인).

### 확보 단어 풀 이관 — 「난이도 결정」은 없었다 (2026-07-27)

`COLLECTED_POOL` 12개 중 **수면제·둔기·유산 상속은 어느 경로로도 공개되지 않았다.**
공개처는 `SEED_TERMS`(2) · `TERM_MAP`(7) · `REVEALS[].terms`(**0 — `terms` 를 가진
항목이 없다**) 셋뿐이고, 이 배열을 읽는 **일곱 곳이 전부** `revealedTerms()` 로
거른다. 후보에 든 적이 없으니 난이도 영향이 0이다 — **기다릴 설계 결정이 아니었다.**

셋을 지우고(아이콘·문안·배열) `applyCase` 가 **엔진 `terms` 순서로 풀을 만든다.**
실측: 풀 9 · 최대 도달 9 · `everyPoolWordReachable = true`. **전에는 12에 9였다.**

> **왜 살아 보였나 — 아이콘과 출처·기록 문안이 다 갖춰져 있었다.** 데이터가
> 완비돼 있으면 도달 가능해 보인다. **도달성은 데이터가 아니라 경로로 센다.**

**같은 자리에서 영문 결함을 하나 더 잡았다.** `applyCase` 가 `ko` 만 덮어써서
엔진이 써둔 `en` 이 버려지고 앱의 낡은 값이 영문 모드에 렌더됐다 — `테이프`·`연탄`
출처가 **피해자 옛 이름** `"Chae-won's room"` 이었다. `GRAPH_NODES` 에서 같은
부류를 잡은 **바로 그날** 이쪽은 살아 있었다. 한 곳을 고칠 때 **같은 모양의 다른
곳을 함께 센다.**

**그리고 조용한 탈락을 없앴다.** 엔진 단어가 앱에 없으면 `continue` 로 삼키던 것을
`console.warn` 으로 남긴다(`영수증 · 물자국` 이 찍힌다). **그 침묵이 영문 결함을
살려뒀다** — 덮어쓸 대상이 없다는 사실 자체가 신호였는데 아무도 안 봤다.

### `INV_ACTIONS` 모델 충돌이 풀렸다 (2026-07-27) — 실제로는 3쌍이었다

「앱 6동사×대상 ↔ 엔진 23구체」라는 표현이 **문제를 실제보다 크게 보이게 하고
있었다.** 엔진 23을 앱 키(`동사:대상`)로 접으니 20이 나왔고 **19는 1:1로 깨끗**,
걸린 것은 셋뿐이었다.

| 앱 키 | 엔진 조사 둘 | 처리 |
|---|---|---|
| `search:main` | `a_kitchen` 주방 · `a_living` 거실 | **`a_main` 본채 수색**으로 합침 |
| `search:annex` | `a_annex` 별채 · `a_storage` 창고 | `a_annex` 유지, 창고 흡수 |
| `fixture:hearth` | `a_briquette` 연탄 · `a_hearth` 화로 | `a_hearth` 유지(상위집합) |

**셋 중 넷이 `gives: []` 인 빈손 조사였고** `a_briquette` 는 `a_hearth` 가 이미
게이트 없이 주던 `e_receipt` 의 중복 경로였다 — **난이도가 움직이지 않았다**
(기대 6 · 오라클 4 · 탐욕 7 전부 불변, 검증 통과). 조사 23 → 20.

**진짜 원인은 따로 있었다 — 엔진에 `verb` 가 없었다.** 동사가 `label` 산문
접두(「소지품 검사 · 」)에만 있어서 `target` 이 있어도 앱 키를 만들 수 없었다.
`target.kind` 로도 못 가른다 — **`belongings` 와 `phone` 이 둘 다 person 을
겨눈다.** `ActionVerb` 여섯을 신설했다. 결과: **조사 20 → 앱 키 20 → 충돌 0.**

> ⚠ **깨진 규약 하나를 적어둔다.** `a_briquette` 에 *"영수증의 2번째 경로.
> 핵심 물증은 경로가 둘 이상이어야 한다"* 는 주석이 있었고 **검증기는 그것을
> 검사하지 않는다**(주석뿐이다). 합치면서 `e_receipt` 의 경로가 하나가 됐다.
> 다만 **두 경로가 같은 고정물에 걸려 있어 앱 입도에서는 애초에 하나였다** —
> 플레이어가 겪을 수 있는 이중화가 아니었다.

**남은 미대응 1건 — `a_victim_bel`(소지품 검사 · 피해자).** 앱에 대응 키가 없고
**엔진에서도 `target` 을 줄 수 없다**: `incident.subject` 가 `chaewon` 인데
`people` 에 없다(피해자는 인물로 모델링되지 않는다). 주는 물증 `e_victim_phone`
은 `planted_in` 으로 사건 논리에 쓰이므로 **지우면 도달성이 깨진다.** 앱 쪽에
피해자 소지품 조사를 만드는 것이 맞다 — 엔진의 잉여가 아니라 앱의 구멍이다.

> **`schema.ts` 화이트리스트에 또 걸렸다.** 고정물 `label` 과 같은 날 같은
> 함정이다 — `types.ts` 에 `verb` 를 더해도 로더가 안 넘기면 배포 JSON 에
> 안 실린다. **엔진 필드 추가는 `types.ts` · `schema.ts` · YAML · `applyCase`
> 넷이 한 벌이다.**

### 고정물 이름표 이관 — 로더가 필드를 삼키고 있었다 (2026-07-27)

`floor_plan.fixtures` 에 `label`(도면 위 한국어 이름표)을 신설했다. 사건마다 다른
어휘이고 **사건 2번의 고정물은 이름이 다르다.** `doors`·`windows` 의 `label` 과
같은 규약이다. **영문과 아이콘은 앱에 남는다** — 영문은 평면도 로마자 표기가
미결이라 방 이름과 같은 처지이고, 아이콘은 인물의 색·이니셜과 같은 표시 속성이다.

> ⚠ **`schema.ts` 가 필드를 화이트리스트로 재구성한다.** 설비를
> `{ x: num(v.x), y: num(v.y) }` 로 **새로 만들어서** YAML 에 `label` 을 적어도
> 로더에서 사라졌다. 스키마·YAML·앱 셋을 다 고쳤는데 **빌드는 초록이었고
> 배포 JSON 에는 `label` 이 없었다** — no-op 를 실을 뻔했다.
>
> **값이 같으면 읽어서는 이관을 증명할 수 없다.** 엔진 라벨이 앱 하드코딩과
> 글자까지 같아서(화로·테이프·금고·시신) 화면을 봐도 통과처럼 보인다.
> 앱 값을 `###` 로 지우고 **실제 배포 파일**로 되살아나는지 봐서 잡았다.
> **이관 검증은 차분으로 한다 — 한쪽을 망가뜨리고 다른 쪽이 고치는지 본다.**

`floorPlan` 에 필드를 더할 때는 **`types.ts` · `schema.ts` · YAML · `applyCase`
넷을 같이 고친다.** `schema.ts` 를 빠뜨리면 조용히 죽는다.

### 엔진에 있는데 앱이 안 쓰는 것

`chapters[].opening`(장 도입 한 줄). 프로토타입 `SECTIONS` 에 그 자리가 없어서
**일부러 안 가져왔다** — 넣으면 죽은 데이터이고 렌더할 자리를 새로 만들면
이식이 아니라 발명이다. 지금까지 「앱에만 있는 것」만 셌는데 반대 방향도 있다.

React 로 뽑으면 이게 그대로 React state 로 나온다. **엔진이 정본이라는 뼈대가

틀리고 앱이 맞는 것들**이라 재export 하면 전부 되살아난다.

**결론: 재export 자체가 나쁜 게 아니라 타이밍이 지났다.** 이식은 끝났고 남은 비용은
만드는 것이 아니라 확인하는 것이다. 다만 `port-check` 가 그 계산을 바꾼다 —
나중에 디자인을 DC 에서 고치고 앱에 반영하는 왕복이 그만큼 싸진다.

## 검증기가 산문을 읽기 시작했다 (2026-07-25)

여태 검증기는 **논리만** 봤다. 유서 버그가 그래서 살아남았다 — *"찾았다"* 는 **문장**과
*"단어를 준다"* 는 **데이터**가 다른 파일에 있으니 어긋나도 아무도 몰랐다.
`MEMORY.md` §오케스트레이터가 「산문↔데이터 정합」 역할이 비어 있다고 적어둔 자리의 첫 조각.

| 검사 | 내용 |
|---|---|
| **9-1** | 지문은 **전원이 갖거나 전원이 없다.** 넷은 담담한데 하나만 불안하면 지문이 곧 범인 표시 |
| **9-2** | 현장 서술이 `seedTerms` 밖 단어를 말하면 오류. **브리핑은 조사 0회 시점이다** |
| **9-3** | 도면 ↔ 장소 정합. **도면에 없는 장소는 플레이어가 갈 수 없다**(조사 화면이 곧 도면) |
| **9-4** | 조사 ↔ 조사 지점 정합. `target` 이 사라지면 **조사가 조용히 실행 불가**가 된다 — 화면엔 아무 일도 없고 예산도 안 줄고 오류도 안 난다 |

음성 테스트 6종 전부 발화·exit 1 확인.

### 난이도 공식을 고쳤다 — 내가 틀렸다

아침에 검증기가 `impossible` 을 띄웠을 때 "공식 아티팩트다, 오라클 4회면 클리어 가능"이라고
설명해 없앴다. **검증기가 맞았고 그 판단이 틀렸다.** 프로 추리 작가가 예산 5를 다 쓰고 못 풀었다.

```
이전   기대 = 탐욕 × 1.5        → 11회 → impossible
지금   기대 = (오라클+탐욕)/2   →  6회 → hard
```

탐욕 시뮬은 **이미** 레드 헤링을 전부 밟는 최악에 가까운 모델인데 거기에 1.5를 또 곱한
이중 계산이었다. 반대로 오라클은 전지적 최단이라 사람이 도달할 수 없다. 실제는 그 사이다.
**이 모델도 실측 1건으로만 뒷받침된다** — 코드 주석에 적어뒀다.

예산은 5 → 6. 필수 3 · 오라클 4 · 탐욕 7이므로 **레드 헤링 하나까지는 감당하고 둘부터 실패한다.**

## 엔진 ↔ 프로토타입 데이터 불일치 (2026-07-24 해소)

같은 산장 사건이 두 곳에 있으면서 어긋나 있었다. 네 건 모두 정리했다.

1. **4장 공란** — 협박대상을 **오나경**으로 확정하고(`design-brief.md` §4.6 L1 그래프가 "김선생 → 나경(협박)"), 4장을 **5공란**으로 늘려 인물 둘을 다 넣었다: 물품·정체·협박대상·인물(리원)·인물(세라). 사건 총 20공란.

   > 다만 **심증 부문 빈약은 이걸로 풀리지 않았다.** `인물`은 `DOMAIN_OF`상 **정황**이다. 정황 9 → 10이 됐을 뿐 심증은 그대로 3이다.

1-1. **`공범` 라벨 폐기** — 심증을 늘릴 후보로 검토했다가 **공란 어휘에서 아예 제거했다.**

   - **누설** — 라벨 존재 자체가 "범인 말고 한 명 더 있다"를 조사 0회에 푼다. `design-brief.md` §3이 이미 같은 경고를 적어놨었다. 가리거나 뒤쪽 절로 밀어도 장을 열면 드러나므로 안 쓰는 것이 유일하게 깨끗한 처리
   - **검증 부담** — 유일성 검사가 인물 1명에서 **인물 쌍**으로 올라간다. "범인 A·공범 B"와 "범인 B·공범 A"를 증거가 구분해야 하고 상호 알리바이 조합까지 배제해야 한다. 생성기가 사건마다 통과시켜야 하는 검사다
   - **핵심 규칙 이음매** — 공범은 살인엔 무고하고 L1엔 유죄라 "무고한 사람은 거짓말하지 않는다"에 예외가 하나 더 붙는다
   - **난이도** — 예산 경고가 이미 떠 있는 상태에서 필수 조사를 더 얹을 수 없다. 기존 조사에 얹으면 공짜 답이 되어 심증 부문이 오히려 쉬워진다

   **진실 세계의 `accomplice` 역할은 남는다.** 채원(다인)이 마약망에 관여했다는 사실은 5장 동기 `폭로 임박`의 전제이고, 관계 그래프 간선은 조사로 얻은 것만 그려지므로 누설이 아니다. **공란으로 묻지만 않는다.**

   부수 효과: 심증 부문이 `동기·정체·협박대상` 3라벨로 확정되어 **실제 심증 3공란과 일치한다.** "심증이 빈약하다"는 인상은 쓰지도 않을 라벨을 세고 있었기 때문이었다. 심증 확장이 정말 필요한지는 플레이테스트 「부문별 성향이 갈리는가」가 답할 질문이다.

2. **확보 단어 획득 그래프 통일** — 한 그래프로 맞췄다.

   | 단어 | 획득 경로 (양쪽 동일) |
   |---|---|
   | 테이프 · 연탄 | **진술 정독 무료** (`Case.seedTerms` 신설) |
   | 일산화탄소 중독 | 시신 정밀 검사 |
   | 유서 | 소지품 검사 · 세라 |
   | 김선생 | 별채 수색 · 소지품 검사 리원 (2경로) |
   | 마약 | 소지품 검사 리원 · 나경 (2경로) |
   | 폭로 임박 | 별채 수색 · 소지품 검사 리원 (2경로) |
   | 별채 대포폰 | 별채 수색 (**1경로**) |

   판정 근거: 마약은 프로토타입이 별채에서 줬으나 **별채 결과문에 마약이 없다** — 엔진(소지품)이 맞다. 폭로 임박은 프로토타입이 4장 확인 무료 보상으로 줬으나 물증에 매다는 엔진 쪽이 맞다. `테이프·연탄`은 반대로 프로토타입이 맞다 — 1장은 조사 없이 확정돼야 하는데 은폐수단=테이프를 채울 수 없으면 시작하자마자 막힌다.

3. **동의어 충돌 제거** — `대포폰`을 확보 단어 풀에서 뺐다. `별채 대포폰` 하나만 남는다. (평면도 단서 마커의 `대포폰` 라벨은 다른 네임스페이스라 그대로 둠)

4. **`presence → 진술 주장 도출` 구현** — 슬롯 어휘를 프로토타입 쪽(`t0~t3`)으로 통일하고 `Case.slots`를 정본으로 만들었다. `Person.presence` = **실제 동선(진실)**, `Person.claim` = **주장이며 생략하면 presence와 같다.** 즉 *무고한 사람은 거짓말하지 않는다*가 데이터 규약이 아니라 **기본값**이다. 도출 함수는 `deriver.ts`(`claimGrid`·`tellsTruth`·`divergentSlots`)이고 검증기가 다섯을 강제한다:

   - 무고한 사람이 `claim`으로 어긋나면 → 오류
   - 범인이 `claim` 없이 진실만 말하면 → 오류 (잡아낼 거짓말이 없다)
   - 범인의 거짓말이 **사망 시간대(`isWindow`) 밖에만** 있으면 → 오류 (알리바이가 반박되지 않는다)
   - `presence`·`claim`·`시각`·`장소` 공란이 `slots`·`locations` 밖 어휘를 쓰면 → 오류
   - **무고한 사람이 사망 시간대에 `incident.scene`에 있으면 → 오류** (기회가 생겨 유일성이 무너진다)

   현재 산장 사건에서 어긋나는 사람은 **세라뿐**이다 (t2·t3 — 주장 별채 / 실제 다인의 방).
   `locations`에 `atLodge` 표식이 있어 산장 밖(백리원의 자택)은 애초에 현장 접근이 불가능하다.

## 장 전환이 뜬금없다 — 플레이 피드백 (2026-07-24)

> "1장은 안 어색한데, 2장에 관련된 내용을 조사로 확인해보지 않은 상태에선
> 갑자기 뜬금없이 점프하는 느낌이 든다."

**어쩔 수 없는 것이 아니다.** 데이터를 보면 원인이 셋으로 갈린다.

### 1. 1·2장이 둘 다 조사 0회로 풀린다

| 장 | requiresFacts | 공란 | 필요 조사 |
|---|---|---|---|
| 1 도착과 발견 | 전부 무료 | 닫힘 3 + `테이프`(seedTerm) | **0회** |
| 2 마지막 정황 | 전부 무료 | 닫힘 4 | **0회** |
| 3 사인과 현장 | `f_cause` + `f_sakura_means` | `사인`·`위장물` 유료 | 부검 + 세라 소지품 |

첫 조사가 실제로 필요해지는 것은 **3장부터**다. 2장은 진술에 답이 다 있다.
즉 막힌 게 아니라 **막혔다고 느끼는** 것이고, 그래서 고칠 수 있는 문제다.

### 2. 게임이 반대 방향을 가리킨다 ← 가장 명확한 결함

1장 완성 시 뜨는 reveal:

```
narration: '도착 정황이 정리됐다. 별채의 존재가 드러나 현장을 넓게 살필 수 있게 됐다.'
facts:     ['f_cause']        ← 언급되지 않는다
actions:   ['a_annex']        ← 이것만 언급된다
surface:   'map'
```

**조사하러 가라고 말한 직후에, 조사가 전혀 필요 없는 2장을 연다.** 플레이어는
별채로 갔다가 돌아와서 "이게 2장이랑 무슨 상관이지?"가 된다. (별채 자체는 4·5장에
필요하므로 낭비는 아니지만 **타이밍 신호가 어긋난다.**)

동시에 이 reveal은 `f_cause`(외상 없음·일산화탄소 중독)를 **조용히** 준다.
3장이 요구하는 바로 그 사실인데 narration이 언급조차 하지 않는다.
**시끄럽게 준 것(별채)은 나중에 필요하고, 조용히 준 것(사인)이 다음에 필요하다.**

### 3. 장이 열릴 때 전환 문구가 아예 없다

프로토타입에 장 열림 내러티브가 **0건**이다. 장은 제목만 달고 차갑게 등장한다.
"현장 정황은 정리됐다. 이제 마지막으로 목격된 시점을 확정한다" 같은 **절차 문구**는
제목이 이미 말하는 것 이상을 누설하지 않으므로 절대 규칙에 걸리지 않는다.
*여기를 조사하라*(금지)와 *수사 절차상 다음은 시간대 확정이다*(허용)는 다르다.

### 그리고 이건 폐기된 설계 절이 경고했던 비용이다

오늘 `⛔ 폐기` 표시를 박은 `design-brief.md` §4.1 「미해금 절도 항목은 보여야 한다」가
정확히 이걸 예측했다:

> 플레이어는 조사 예산 5회를 배분해야 하는데, **무엇을 알아내야 하는지 모르는 상태에서
> 배분하게 된다.** 이는 난이도가 아니라 불공정이다.

그 절은 라벨을 노출하자고 했고, 그건 사건 구조를 누설하므로 폐기된 게 맞다
(`물품·정체·협박대상`만 봐도 숨은 범죄가 드러난다). **하지만 폐기는 누설을 막았을 뿐
근본 문제를 풀지 않았다.** 잠긴 장이 번호만 남으므로 수사의 형태가 보이지 않고,
매 장이 예고 없이 도착한다. 지금 느끼는 것이 그 대가다.

### 결정 (2026-07-24)

| | 내용 | 상태 |
|---|---|---|
| **A** | **장 열림 문구 추가.** 각 장에 절차 한 줄 | **확정.** DC에서 처리 |
| **B** | **1장 reveal narration이 `f_cause`를 언급하도록** | **확정.** DC에서 처리 |
| **F** | **장 인터루드** — 장 사이 전체화면 소설체 서술 | **확정.** React 이식 때 구현 (아래) |
| C | 보고서 형식을 처음에 설명 | 보류. 장 구성 다양성과 충돌 |
| D | 다음 장 제목 1칸 미리 보이기 | 보류. 제목도 누설(`감춰진 사건`) |

**B 주의 — 순서로 순위를 매기지 말 것.** 처음에 "사인을 먼저 말하라"고 적었으나
그것은 *다음에 필요한 순서*로 정렬하는 것이라 유용도 누설이다. 문제는 순서가 아니라
**사인이 아예 언급되지 않는 것**이다. 둘 다 말하되 무게를 같게 둔다.

부수 결함: 그 reveal의 `surface`가 `'map'` 하나인데 사인은 **사건 개요**로 가야 한다.
`surface`가 단일 값이라 두 목적지를 표현하지 못한다 — 다중화 필요.

## 장 인터루드 (F) — 설계 확정, 구현은 이식 때

**1장 완성 → 전체화면 소설체 서술 → 2장 열림.** 프롤로그 리더를 재사용한다.

`Reveal.narration`이 엔진에 이미 있고 5개 다 쓰여 있는데 **프로토타입이 한 번도
렌더하지 않는다**(현재 화면의 `narration`은 전부 평면도 조사기록이다). 인터루드가
이 필드의 첫 소비자다.

### 서술자는 두 번 말한다 (2026-07-24 확정)

```
수사 중 (인터루드)      무엇이 도착했는가만
최종 제출 후 (에필로그)  전부
```

같은 목소리인데 **면허가 다르다.** 전환점은 최종 제출 하나뿐이다.

| | 인터루드 | 에필로그 |
|---|---|---|
| 무엇이 도착했나 | 말한다 | — |
| 도착물의 내용 | **카드가** 보여준다 (관찰만) | — |
| 도착물끼리의 **관계** | **말하지 않는다** | 말한다 |
| 인물의 태도 | **말하지 않는다** | 말한다 |
| 트릭 · 동기 | **말하지 않는다** | 전부 |

핵심은 「도착물끼리의 관계」다. *부검 소견이 왔다* ○ · *별채가 있다* ○ ·
**둘이 이어진다 ✗**. 잇는 것이 플레이어의 일이다.
접속사로도 새어 나간다 — `그리고`·`그러나`는 되지만 **`그래서`·`따라서`·`때문에`는 안 된다.**

### 인물 묘사 금지 — 역방향 누설 때문

인터루드는 **인물의 태도·표정·망설임을 묘사하지 않는다.** 분위기는 **무대**에 얹는다.

```
✗ 오나경은 한동안 자리를 뜨지 않았다        (인물에 시선)
○ 해가 기울었고 아직 아무도 불을 켜지 않았다  (무대에 분위기)
```

**decoy 인물을 주목하게 하는 것은 괜찮아 보이지만 함정이다.** 4번 반복되면
*"서술자가 머무는 인물은 한 번도 범인이 아니다"* 가 학습되고, 플레이어가
소거법으로 범인을 찾는다. **어떤 규칙적 패턴이든 신호가 되고 역방향 누설도 누설이다.**
인물 4명에 인터루드 4개면 균등 배분도 불가능하다. 무대는 누구도 가리키지 않는다.

### 안전 규칙 둘 — 이게 없으면 절대 규칙을 깬다

**1. 도착한 사건을 말하고, 내용은 말하지 않는다.**

```
○ "오후 늦게 오나경이 다시 문을 두드렸다. 아까 빠뜨린 게 있다고 했다."
✗ "오나경은 새벽에 자신도 피해자와 통화했다고 털어놨다."
```

아래는 둘이 동시에 깨진다 — 진술 화면에 갈 이유가 사라지고, **주장이 서술자
목소리로 나오면서 확정 층으로 승격**된다(실선/점선 혼용 금지).

**2. decoy와 path를 같은 무게로 집필한다.**

장 완성 reveal의 유용도는 `1장→path · 2장→decoy · 3장→decoy`다.
**소설체로 쓰면 path 쪽이 저절로 더 잘 써진다.** 작가가 의식하지 않아도 그렇게 되고,
그 순간 인터루드 자체가 `유용도 시각 구분`이 된다. 토스트는 균일해서 이 문제가
없었다 — **산문이 만들어내는 새 누설 통로다.**

### 검증기 검사 (구현 시 추가)

- 장 완성 reveal 중 **일부만** interlude를 가지면 → 오류 ✅ 구현됨
- path/decoy 간 문단 수 차이가 크면 → 경고
- **전환별 화면 수 편차가 크면 → 경고.** 특히 `path` 전환이 `decoy` 전환보다
  일관되게 길면 화면 수가 곧 유용도 표시가 된다
- **인과 접속어**(`그래서`·`따라서`·`때문에`)가 인터루드에 있으면 → 경고.
  기계적으로 잡을 수 있다
- **범인 언급 빈도가 다른 인물보다 높으면 → 경고.** 시선 편중의 대리 지표다.
  작가가 무의식적으로 범인을 더 자주 쓰는 것을 숫자로 막는다

> 문장이 실제로 무엇을 암시하는가는 기계가 못 잡는다. 위 넷은 대리 지표일 뿐이고
> 최종 판단은 사람이 한다.

### 시퀀스 구조 (2026-07-24 확정)

오프닝(프롤로그 → 다음 → 진술 정독)을 장 전환에 그대로 재사용한다.

```
N장 완성 → [서술 5문단] → 다음 → [도착물 화면 0~n개] → 다음 → N+1장 열림
```

**도착물은 층위에 따라 전달 방식이 갈린다.** 인터루드는 새 화면을 발명하지 않고
이미 있는 카드를 전체화면으로 한 번 보여줄 뿐이며, **그 카드는 원래 화면에 영구히 남는다**
(전체화면은 전달이지 보관이 아니다).

| 도착물 | 층위 | 전달 |
|---|---|---|
| 새 진술 (`addClaims`) | **주장** | 전용 화면 — 인용·기울임·인물색 레일 |
| 새 물증 (`evidence`) | **확정** | 전용 화면 — 물증 카드 그대로(`extra` 포함) |
| 사실 (`facts`) · 시각 축소 (`narrowsWindow`) | **확정** | 전용 화면 — 사건 개요 갱신 형태(이전 값 취소선) |
| 새 장소 (`actions`) | **확정** | 전용 화면 — 평면도 컴포넌트 그대로 |

> **한때 "조사 대상 열림은 접근 권한이지 읽을 것이 아니니 서술에 녹인다"고 적었는데 틀렸다.**
> 별채는 *몰랐던 공간이 존재한다는 사실*이고, 평면도가 그 확정 층의 시각 언어다.
> 더 중요한 것은 **예외를 두는 것 자체가 누설 통로**라는 점이다 — 진술·물증·사실은
> 화면을 받는데 장소만 안 받으면 그 불규칙이 신호가 된다.
>
> **도착하는 것은 전부 화면을 받는다. 균형은 예외로 맞추는 게 아니라 검증기가 잡는다.**

### 평면도 화면의 규율

- **확대하지 않는다.** 도면 전체가 그대로 나오고 새 공간은 제자리에 있다.
  확대·화살표·펄스는 전부 "여길 봐"가 된다
- 공개 칩은 **평면도가 이미 쓰는 것**을 쓴다. 인터루드용 새 표현을 만들지 않는다
- **읽기 전용.** 인터루드에서 조사를 실행할 수 없다. 조사는 현장 화면에서
- 시신 X·고정물·창문 3선 전부 그대로. 새로 열린 공간만 특별대우하지 않는다

### 분량 위험 (미검증)

화면 수를 실제로 세면 `1→2`가 **4화면**(서술 + 유빈 진술 + 개요 갱신 + 평면도),
`2→3`이 **3화면**(서술 + 진술 2개)이다. `path`가 `decoy`보다 길다 — 미세하지만
**사건 저작으로 맞춰야 하고 검증기가 경고해야 한다.**

그리고 전환 4번 × 3~4화면 = **사건당 12~16화면이 추가된다.** 오프닝 10화면까지 더하면
상당한 분량이다. **플레이테스트가 답할 항목이다 — 지금 판단할 근거가 없다.**

### 균일성은 구조로 보장한다

산문을 **reveal이 아니라 장에 매단다.** `Chapter.opening`(오늘 신설, `string` → `string[]`로 확장)은
검증기가 이미 전 장 필수로 강제하므로 **서술은 구조적으로 균일**해지고, 뒤에 붙는
도착물 화면 수만 자연스럽게 달라진다. 도착물이 0개인 전환도 서술은 똑같이 나온다.

오늘 넣은 `opening` 한 줄이 그대로 인터루드의 첫 문단이 된다 — 버리는 것이 없다.

### 건너뛰기는 없앤다 (인터루드 · **프롤로그 둘 다**)

진술을 정독시키는 게임에서 건너뛰기는 "이건 안 읽어도 된다"는 말이고,
인터루드는 새 정보를 나르는 화면이라 건너뛰면 못 보고 지나간다.
사건이 1회성이라 재플레이 피로 문제도 없다.
**대신 점 인디케이터가 유일한 "곧 끝난다" 신호가 되므로 반드시 둔다.**

### 에필로그 — 분기하지 않는다 (2026-07-24 확정)

최종 제출 → 채점 → **결말**. 프로토타입에 `epilogue` 문자열 **0건**이고 엔진에만 있다.

**정답자용 / 오답자용으로 나누지 않는다. 모두 같은 진실 서사 하나.**

1. **진실은 플레이어의 답에 따라 변하지 않는다.** 변하면 그건 진실이 아니라 논평이다
2. **게임이 두 번 말하게 된다.** 채점 화면이 이미 맞췄는지 말해준다. 에필로그까지
   반응하면 절대 규칙("판단에 대해 하는 말은 최종 채점 하나뿐")을 최종 화면에서 스스로 깬다
3. **같은 문장이 이미 양쪽에서 다르게 작동한다.** *"김선생은, 세라였다"* 는 맞춘 사람에겐
   확인이고 틀린 사람에겐 정정이다. **문장을 나눌 필요가 없다 — 독자가 이미 다르다**
4. 집필 비용 2배 + 생성기가 못 만든다

대비가 일을 한다: **방금 자기가 쓴 답을 들고 진실을 읽는다.** 분기 콘텐츠가 필요 없다.

> ⚠ 엔진 `Chapter.epilogue` 주석의 *"공란은 `{blank_id}`로 참조하며 플레이어의 답이
> 꽂힌다"* 는 이 결정과 어긋난다. 그 방식(B안)은 틀린 사람에게 **자기 오답으로 쓰인
> 이야기**를 읽히는 것이라 진실을 끝내 말해주지 않는다. **주석을 고쳐야 한다.**

**3·5장 결말 텍스트는 다시 써야 한다** — 트릭 복원 전에 쓰인 것이라 5장이
*"별채에서 연탄을 들고 본채로 향했다"* 로 끝나고 탈출이 없다.

### 스키마·비용

- `Chapter.opening: string` → `string[]`(문단). **선택 항목 유지** — 생성 사건(일일)은
  소설체를 뽑을 수 없으므로 필수로 만들면 생성기가 막힌다
- **`Reveal.evidence?: EvidenceId[]` 신설 필요.** 지금은 물증이 **오직 조사로만** 들어와서
  "장 완성 시 현장에서 새 물증이 나온다"를 표현할 수 없다. 추가는 한 줄이지만
  **검증기 파급이 있다** — `deriveTerms`와 필수 조사 검사가 둘 다 "물증 = 조사의 산물"을
  전제로 계산하므로 무료 물증이 생기면 최단 경로와 필수 조사 수가 바뀐다.
  동시에 이것은 **난이도 손잡이**다(예산을 쓰지 않고 주는 물증). 캠페인 페이싱에 쓸모가 있다
- 집필 비용: 사건당 4개 × 5~10 사건 = 20~40 단락. **코드가 아니라 글이 비용이다**
- DC에 만들면 이식 때 두 번 만들게 되므로 **React에서 한 번만 만든다**

## 태그라인이 핵심 규칙과 반대다 (미해결 · 프로토타입)

| 위치 | 문구 |
|---|---|
| **홈 화면 태그라인** (가장 큰 노출) | **"모든 진술을 의심하라"** |
| 사이드바 주석 (1302행) | "범인만 거짓말을 할 수 있다. 무고한 사람은 거짓말하지 않는다" |

이 게임의 배제는 **전적으로** 후자에 기댄다. 오나경은 자기 진술("장 보고 아침 도착")로
배제되는데, 규칙을 모르면 배제가 성립하지 않는다. **모든 진술을 의심하면 아무도
배제할 수 없고 퍼즐이 원리적으로 안 풀린다.** 테스터가 *"왜 조유리가 아니고 사쿠라지?"*
라고 물은 뿌리다 — 시킨 대로 했을 뿐이다.

~~**제안: 태그라인을 「무고한 사람은 거짓말하지 않는다」로.**~~

> ### 결정 (2026-07-25) — **태그라인은 그대로 둔다. 문제는 다른 곳에 있다**
>
> 위 제안대로 앱에 「무고한 사람은 거짓말하지 않는다」를 넣었다가 되돌렸다.
> 사용자 판단이고, 근거가 셋이다.
>
> 1. **태그라인은 규칙이 아니라 캐치프레이즈다.** 홈 화면 최상단은 홍보의 자리이지
>    설명서의 자리가 아니다. 「모든 진술을 의심하라」는 *누가 범인인지 모른다*는
>    이 장르의 약속을 파는 문구다
> 2. **제목과의 반어가 그 문구의 값이다.** *Nobody Lies* ↔ *모든 진술을 의심하라* —
>    이 긴장이 곧 후크다. 규칙 문장으로 바꾸면 긴장이 사라진다
> 3. **바꾼 문구는 제목과 같은 말이었다.** 「무고한 사람은 거짓말하지 않는다」는
>    *Nobody Lies* 의 한국어 풀이에 가깝다. 홈 화면이 같은 소리를 두 번 하게 된다
>
> **그럼 테스터가 못 푼 문제는?** 그것은 진짜다. 다만 원인이 태그라인이 아니라
> **규칙이 게임 안에서 규칙으로 전달되지 않은 것**이다. 위 표의 두 번째 줄이 이미
> 말하고 있다 — 규칙은 사이드바 주석에 작게 들어가 있었다.
>
> 고칠 곳은 홈이 아니라 **게임 안**이다. 후보:
> · 브리핑에 수사 원칙으로 한 줄 (진입 흐름 안, 확정 층)
> · 사이드바 상시 노출 (프로덕션 앱은 이미 그렇게 하고 있다)
> · `표기 안내` 화면 (프로토타입에 있는 항목)
>
> **어느 것이 충분한지는 플레이테스트가 답한다.** 지금 판단할 근거가 없다.

## 오케스트레이터 — 역할 다섯 (2026-07-24 확정)

> 목표: 앱이 스스로 시나리오를 만들고 검증하고 배포한다. 플레이어는 즐기기만 한다.

| | 역할 | 수단 | 상태 |
|---|---|---|---|
| 1 | **작가(구조)** — 진실 세계·물증·조사·공란 | 코드 | `generate.ts` **스텁** |
| 2 | **비평가(논리)** — 유일성·교착·트릭 계약·회수 | 코드 | `verifier.ts` |
| 3 | **실험자(난이도)** — 경로·예산 탐색 | 코드 | `orchestrate.ts` |
| 4 | **산문가** — 진술·프롤로그·인터루드·에필로그 | **LLM 빌드타임** | 없음 |
| 5 | **검열관** — 산문이 데이터보다 더 말하는가 | **LLM + 규칙** | 없음 |

**작가를 둘로 나눈 것이 핵심이다.** 구조 작가는 순수 코드(기기에서 돌고 오프라인),
산문가는 LLM(빌드 타임, 결과는 파일에 고정). 실행 위치도 검증 방식도 다르다.
`검열관`은 `SYSTEM-DECISIONS.md` 빌드타임 LLM 4곳 중 "UGC 산문 누설 검사"를
생성분 전체로 확장한 것이다. (반쪽 여섯 번째: **번역가** — 어휘 고정이라 값싸다)

### 왜 셋으로 부족한가 — 오늘의 실패를 분류한 결과다

| 실패 | 잡았어야 할 역할 |
|---|---|
| 밀실 탈출 불가 | 비평가 ✅ 해결 |
| 예산 부족 | 실험자 ✅ 해결 |
| 레드 헤링 미회수 | 비평가 확장 ⚠ |
| 유서 "찾았다"는데 단어 미지급 | **산문↔데이터 정합** ❌ |
| 관계 그래프가 답을 그림 | **누설 검사** ❌ |
| 결말이 옛 트릭을 서술 | **산문↔데이터 정합** ❌ |

**아래 셋이 전부 산문 계층이고, 현재 세 역할은 산문을 한 번도 읽지 않는다.**

### 여섯 번째는 만들 수 없다

**"재미있는가"를 판정하는 에이전트는 없다.** 산장 사건은 검증 초록이었는데
프로 추리 작가가 플레이하고 *"왜 조유리가 아니고 사쿠라지?"* 라고 물었다.

> 루프가 보장하는 것은 **풀린다**와 **누설하지 않는다**뿐이다.
> **재미있다**는 플레이테스트만 답한다.

다만 실험자를 늘려 대리 지표는 잴 수 있다(재미가 아니라 상관물):
**선택의 분산** · **정보 도착 리듬** · **레드 헤링 매력도(salience 격차)**.
셋 다 계산 가능하고 셋 다 2026-07-24 테스터 불만과 겹친다.

### 선행 조건 — 산문이 사건 파일에 없다

진술 원문·조사 결과문·물증 기록 대부분이 아직 프로토타입에 하드코딩돼 있다.
**산문이 스키마 밖에 있으면 산문가도 검열관도 설 자리가 없다.**

그리고 그것이 유서 버그의 뿌리다 — "찾았다"는 **문장**과 "단어를 준다"는 **데이터**가
다른 파일에 있으니 어긋나도 아무도 모른다. 한 파일에 있으면 기계가 잡는다.

```
지금   논리 = YAML · 산문 = DC 하드코딩
다음   논리 + 산문 = 한 파일
```

### 캠페인 자동 생성은 미해결

`SYSTEM-DECISIONS.md`가 "생성기는 daily 만, campaign 은 사람이 쓴다"고 못박았고
현재 `generate.ts`도 daily 고정(3인·2장·6공란)이다. 논리 쪽 경계는 오늘 트릭이
계약이 되면서 밀렸지만 **캠페인의 값어치는 대부분 산문에 있다.** 다시 볼 만한
결정이나 지금 뒤집을 근거는 없다.

```
1. 문서 모순 정리                                 ← 2026-07-24 완료
2. 엔진 ↔ 프로토타입 데이터 동기화 + 재검증        ← 2026-07-24 완료

3b. 병렬 세션 통합 (main ↔ 브랜치)                 ← 2026-07-25 완료
3c. DC 잔여 5건 저장소·배포본 반영                 ← 2026-07-25 완료 (DC 마스터는 미반영)
4. 플레이테스트                                    ← 테스터 1명으로 좁혀짐

6. 프로덕션 구현      ← ★ 2026-07-25 착수. 아래 참조
```

**순서가 바뀌었다 (2026-07-25).** 테스터가 1명으로 좁혀지면서 "3명 더 배포"가 없어졌고,
장 전환의 뜬금없음 같은 큰 결함은 이미 1차에서 나왔다. 그래서 프로덕션을 먼저 시작하고
플레이테스트는 병행한다. 인터루드도 프로덕션에서 만든다 — DC에 만들면 두 번 만든다.

### 프로덕션 진행 상황 (2026-07-25)

```
✅ 진입 흐름     홈 → 사건 상세 → 프롤로그 → 브리핑 → 진술 정독
✅ 자유 진행 셸   사이드바 · 상단 헤더 · 우측 디테일 패널(교차 참조)
✅ 보고서        5장 · 순차 잠금 · 공란 3상태 · 자동 완성 · 재개봉 · 확보 단어 은행
✅ 마킹 시스템    드래그 4색(표시·확인·의심·모순) · 인용→메모 · 복사
✅ 진술 화면      D안 조판(좌측 레일 + 아코디언) · 추가 진술
✅ 사건 개요      프롤로그 재수록 · 인용 툴바 · 갱신 배지 · 이전 값 취소선
✅ 용의자         심증(제외/주목/유력) · 동기·기회·수단 · 소지품·통화 조사
✅ 현장           평면도(GEO) + 도식(주장 대조표) 두 탭
✅ 조사 시스템    평면도·용의자 카드에서 실행 · 예산 차감 · 결과 카드 · 조사 기록
✅ 모달 인프라    포기 확인 · 제출 확인 · 조사 확인 · 토스트
⬜ 관계 그래프 · 상황판 ⚠(미결)
⬜ 메모 화면 · 표기 안내
⬜ 최종 제출 · 채점 · 결말
⬜ 장 인터루드
```

**게임이 2장 너머로 뚫렸다.** 시신 정밀 검사 → 예산 6→5 → 확보 단어에
`일산화탄소 중독` 추가까지 실측 확인. 3장의 `사인` 공란이 열리는 경로다.

**표기 안내는 맨 뒤로 미뤘다** — 완성된 게임 **전체의 범례**라서, `newStates` 14항목이
관계 그래프·상황판·평면도·현장 조사를 설명하고 `sounds` 4항목은 아직 없는 소리를
설명한다. 지금 옮기면 범례의 절반이 거짓말이 된다.
(부수 발견: `autoTag`(자동)는 데이터에서 한 번도 켜지지 않는다 — 폐기된 「모순 경고」
설계의 잔해이므로 **이식하지 않는다.**)

**4번이 시작됐고 이미 값을 했다.** 시나리오 작가 1명이 플레이하고 다섯 건을 찾았다 —
밀실 탈출 구멍 · 유서 진행 차단 · 관계 그래프 누설 · 레드 헤링 미회수 · 난이도.
**전부 검증 초록인 상태에서 살아 있었다.** 오늘 추가한 검사 대부분이 그 피드백을
기계가 잡을 수 있는 형태로 옮긴 것이다.

### 병행 트랙 — 오케스트레이터

플레이테스트와 무관하게 굴러가는 축이다. `4a` 회신을 기다리는 동안 진행한다.

```
A-1  산문 스키마 설계        ← 2026-07-24 완료 (Text·statement·result·prologue·terms)
A-2  산문 이관              ← B 회신 후. 진술 원문·조사 결과문·확보 단어 정보
A-3  작가에 구조 변이        ← 지금 100% 통과는 템플릿 하나뿐이라 그렇다
A-4  통과분을 YAML로 쓰기    ← '배포'의 첫 조각. 로더의 반대 방향
```

### ⚠️ 저장소는 프로토타입의 원본이 아니다 (2026-07-24 발견)

3번을 처리하다 드러났다. **오늘 아침 커밋(`cb524e2`)에 들어간 `추리게임.dc.html`이
이미 Claude Design 워크스페이스보다 401줄 뒤처진 스냅샷이었다.** 현장 평면도 엔진
전면 재작성(`GEO` 스키마 · poché 외벽 · 문 스윙 아크 · 창문 3선 · 축척바)이 통째로 빠져 있었고,
그 낡은 사본 위에서 데이터 수정을 하고 있었다.

규칙으로 박아둔다:

> **프로토타입을 고칠 일이 생기면 저장소 파일부터 고치지 말 것.**
> Claude Design 워크스페이스가 원본이고 저장소는 사본이다.
> 갱신은 핸드오프 export를 받아 통째 교체하는 방식으로만 한다.

엔진(`engine/`)과 문서(`docs/`)는 반대로 저장소가 원본이다.

**그리고 다른 기계가 정확히 그 규칙을 어겨서 이 통합의 비용이 됐다 (2026-07-25 확인).**
`main` 쪽 세션이 저장소 사본에 데이터 수정 7건을 직접 넣었고, 브랜치 쪽은 DC 핸드오프로
파일을 통째 교체했다. 병합 시 **DC export 를 정본으로 채택**하고(그쪽이 평면도 GEO 엔진과
상황판 인라인을 갖고 있어 상위집합), 저장소 사본의 수정분은 export 를 한 줄씩 대조해
갈랐다:

| | |
|---|---|
| **이미 DC에 반영돼 있던 것 4건** | `b15 = 조유리` · `TERM_MAP` 재구성(`belongings:wonyoung` 신설 포함) · `REVEALS.s4` 무료 공개 제거 · `COLLECTED_POOL`의 `대포폰` 제거 |
| **아직 DC에 없던 것 5건** | `공범` 라벨 4곳 · 4장 문장틀 · `별채 대포폰` 서술 · 발견 위치 · **인물명 교체** |

`prototype/DC-SYNC-CHANGESET.md` 를 2026-07-25에 **실제 export 를 확인해 다시 썼다** —
이전 버전은 이미 적용된 것까지 적고 있었다.

**그리고 남은 5건을 저장소 사본과 배포본에 직접 적용했다 (2026-07-25).** 플레이테스트를
더 미룰 이유가 없어서다. 옛 이름 잔존 0건, 치환 전후 출현 수 1:1 일치를 확인하고
(세라 16 = 쿠라 16 · 다인 36 = 채원 36 …) 배포본을 브라우저로 열어 렌더·순차 잠금·
콘솔 에러 0 을 확인했다. `b15` 의 조사(`par`)도 새 문장에 맞춰 `'을/를'` 로 고쳤다 —
문장을 바꾸면 조사가 따라가야 한다.

> ⚠️ **DC 워크스페이스는 여전히 옛 상태다.** 저장소만 고친 것이라 **거기서 재export
> 하는 순간 5건이 전부 사라진다.** changeset 은 그래서 지우지 않고 남긴다.
> 이것은 "저장소부터 고치지 말 것" 규칙을 **의도적으로 어긴** 경우다 — 플레이테스트가
> 그만한 값을 하고, 되돌릴 목록이 파일로 남아 있다.

**4번이 가장 큰 미검증 가정이다.** 이 게임은 아직 한 번도 (앱으로) 플레이된 적이 없다. 40개 넘는 설계 결정이 미검증이고, 특히 검증기가 예측한 "조사 5회"가 실측과 맞는지 모른다. **그 숫자가 틀리면 난이도 체계 전체가 다시 계산되고 생성기 신뢰도가 무너진다.**

플레이테스트에서 측정할 것: 진행자 없이 재미있는가 / 몇 회에 풀었는가 / 부문별 성향이 갈리는가 / 순차 잠금이 답답한가 긴장인가 / 완전 침묵이 가혹한가 / **격자·상황판·관계 그래프를 실제로 쓰는가** / 어디서 지루한가 / 진술 5개가 머리에 들어오는가 / **장이 열릴 때 뜬금없다고 느끼는가 — 특히 2장** (위 절 참조).

프로덕션 구현 순서는 `design-brief.md` §7 우선순위 표를 그대로 쓴다.

## §구조 백로그 — 이번 수리의 범위가 아니다

> 지시서 §2: *"구조 리팩터링이 필요해 보이는 항목은 고치자고 쓰지 말고 여기 모은다
> — 언젠가 올 UI 재작성의 입력이지 이번 수리의 범위가 아니다."*

- ★ **`buildReadCard()` 무가드 — 앱 전체가 죽는다.** `renderVals` 가 화면과
  무관하게 **매번** 부르는데(`App.jsx:3476`) 내부는 `PEOPLE[readIdx].name` 을
  가드 없이 읽는다(`:1971`). `readIdx` 는 **저장되는 값**이고 `PEOPLE` 은 **사건
  파일에서 온다** — 둘이 어긋나면 「렌더 실패」로 앱이 통째로 멈춘다.
  감사 중 심은 값(`readIdx:5`)으로 **실제로 재현했다.** 정상 플레이에서는
  `finishRead()` 가 인덱스를 `length-1` 에 두므로 안 나지만, **인물 수가 다른
  사건으로 저장이 넘어가면 나는 구조**다.
- `App.jsx` 4,564줄 단일 클래스 (①에서 −681줄 했으나 여전히).
- 반응형 어휘가 CSS 에 0 — 새 breakpoint 체계는 수리 배치의 설계 대상이다.
- 인라인 스타일 713회가 스킨 배치의 실질 선행 조건 (#12).

## 도구가 자기를 두 번 속였다 (기록)

- **터치 타깃을 「하나라도 44 미만」으로 세어 100% 가 나왔다.** 넓고 낮은
  사이드바 행이 전부 걸린 것이라 **손가락이 빗나가는 부류가 아니었다.**
  둘 다 미만 / 낮기만 / 좁기만 으로 갈라 다시 쟀다(72 · 42 · 0).
- **`더보기` 로 좁은 폭 다섯 화면을 못 찾았다.** 실제 라벨이 `더 보기`(사이 공백)다.
  **눈에 같아 보이는 것이 코드에 같지 않다** — 공백을 지우고 비교하도록 고쳤다.

## §구조 백로그 — 이번 수리의 범위가 아니다

> 지시서 §2: *"구조 리팩터링이 필요해 보이는 항목은 고치자고 쓰지 말고 여기 모은다
> — 언젠가 올 UI 재작성의 입력이지 이번 수리의 범위가 아니다."*

- ★ ~~**`buildReadCard()` 무가드 — 앱 전체가 죽는다.**~~ → ✅ **닫혔다 (2026-08-06 ·
  사용자가 수리-A 로 예외 승격).** `renderVals` 가 화면과 무관하게 **매번** 부르는데
  내부는 `PEOPLE[readIdx].name` 을 가드 없이 읽고 있었다. `readIdx` 는 **저장되는
  값**이고 `PEOPLE` 은 **사건 파일에서 온다** — 둘이 어긋나면 「렌더 실패」로 앱이
  통째로 멈춘다. 감사 중 심은 값(`readIdx:5`)으로 **실제로 재현했었다.**
  → 이제 `emptyReadCard()` 로 떨어진다. **가드를 호출부가 아니라 `buildReadCard`
  안에 뒀다** — 호출부에 걸면 다음 호출부가 생길 때 같은 자리에서 다시 죽는다.
- `App.jsx` 4,564줄 단일 클래스 (①에서 −681줄 했으나 여전히).
- 반응형 어휘가 CSS 에 0 — 새 breakpoint 체계는 수리 배치의 설계 대상이다.
- 인라인 스타일 713회가 스킨 배치의 실질 선행 조건 (#12).

토큰화해도 게임 화면 스킨이 선다"* 였다. **전제가 둘 다 틀렸다.**

### ① 개발 도구가 아니다 — 사용자 화면이다

```
홈 「캠페인 생성 · 새로 만들기」 카드 → goRoute('generate')   App.jsx §home
  캠페인 목록에 네 사건과 나란히 · var(--accent) 점선 테두리로 눈에 띄게 놓았다
main.jsx  #generate → import('./Generator.jsx')              dev 가드 **없음**
프로덕션 번들에 실린다  dist/assets/Generator-*.js  262.64 kB
MANIFESTO §사건이 생기는 길은 셋이다 — "② 생성기 … ★ **유저용** · Generator.jsx"
```

**UGC 가 상품이므로 오히려 스킨이 제일 필요한 화면 축에 든다.**

### ② 그런데도 범위는 줄었다 — **이미 토큰화돼 있어서**

```
Generator.jsx   hex 76  →  var() 폴백 74 · 진짜 2
App.jsx         hex 23  →  폴백 0 · 진짜 23   (그중 15가 인물 색 = 데이터)
main.jsx        hex  1  →  진짜 1
전체           100건    →  **26건**
```

⛳ **답이 「범위 밖」이 아니라 「이미 했다」다.** 그래서 결론은 같은 방향인데
**이유가 반대**고, 그 차이가 중요하다 — 「범위 밖」으로 닫았으면 `Generator` 의
남은 2건과 **폴백 74건이 가리키는 토큰 이름들**을 스킨 설계에서 통째로 놓쳤을 것이다.
**저 74개가 곧 스킨이 덮어야 할 토큰 목록이다.**

## 도구가 자기를 네 번 속였다 (기록)

- **터치 타깃을 「하나라도 44 미만」으로 세어 100% 가 나왔다.** 넓고 낮은
  사이드바 행이 전부 걸린 것이라 **손가락이 빗나가는 부류가 아니었다.**
  둘 다 미만 / 낮기만 / 좁기만 으로 갈라 다시 쟀다(72 · 42 · 0).
- **`더보기` 로 좁은 폭 다섯 화면을 못 찾았다.** 실제 라벨이 `더 보기`(사이 공백)다.
  **눈에 같아 보이는 것이 코드에 같지 않다** — 공백을 지우고 비교하도록 고쳤다.

### ⛔ 셋째 — **56장의 캡처가 전부 홈 화면이다** (2026-08-06 · 아직 안 고쳤다)

수리-A 재측정 중에 `log-mid-mobile.png` 를 열었더니 **조사 기록이 아니라 홈**이었다.
`report-mid-mobile` 도 `log-mid-laptop` 도 같았다. 재보고 원인을 확정했다:

```
seed(localStorage) → page.goto(BASE)   앱이 route:'home' 으로 뜬다
goto(page, '조사 기록')                 setView() 를 부른다 — view 는 바뀐다
                                        그런데 **route 는 'home' 그대로**다
홈은 position:fixed · z-index:70 의 덮개고, 게임 셸(.app)은 그 **밑에 깔린 채**다
```

**`elementFromPoint` 로 확인했다** — 셸의 `.iconbtn` 여섯이 전부 `visible:false`
(덮개에 가려짐)이고, 실제로 눌리는 것은 홈 자신의 것 하나뿐이다.

```
스크린샷    ⛔ 이름이 가리키는 화면이 아니다. 56장 전부 홈이다
크롤 수치    ⚠ 화면마다 다르긴 하다 (pads 14~21 · overflow 0~13) — 덮개 **밑에 깔린**
             셸을 재기 때문이다. 즉 **의도한 화면을 재긴 하는데, 그 순간 화면에 없는
             요소**를 재고 홈 덮개의 요소와 **섞어서** 센다
```

⛳ **그래서 「인터랙티브 115개」 같은 합계는 두 층이 섞인 수다.** 화면별 행(#4~#6 ·
#16 · #17)을 **한 화면의 실측으로 읽으면 안 된다.**

> ★ **수리-A 의 72 → 0 은 이 결함과 무관하게 참이다.** 문제의 일곱 개는 두 층 **모두**에
> 있고, 덮개를 걷은 실제 게임 화면에서 **375·1280 둘 다 `bad: 0`** 을 따로 확인했다.
> 반대로 **표의 나머지 행은 이 결함을 걷어내고 다시 읽어야 한다.**

### ✅ 셋째 — 같은 날 닫혔다 (`enterGame()`)

수리-A 를 **먼저 커밋해서 경계를 지키고**(전후 비교가 섞이지 않게), 그 뒤에
`goto()` 앞에 홈 덮개를 걷는 한 걸음을 넣었다.

★ **①만 넣었더니 `report-done-*` 넷이 「홈 덮개를 못 걷었다」로 떨어졌다.**
`resumeShow` 는 `status === 'inProgress'` 일 때만 참이라 **다 푼 사건은 홈 배너가
없다**(입구가 사건 상세의 「다시 보기」다). 그래서 ②를 붙였다.
**검사가 자기 구멍을 이름으로 말해준 것이다** — 조용히 홈을 찍는 것보다 낫다.

★ **`enterGame` 은 「눌렀나」가 아니라 「걷혔나」를 돌려준다.** 옛 조용한 실패가
정확히 그 차이에서 났다 — `.click()` 은 **가려져도 먹으므로** `goto()` 는 내내
「성공」을 돌려주고 있었고, **덮였는지는 아무도 안 물었다.**

```
캡처      56 → 60 (홈 넷이 늘었다)    못 잰 것 0
오염 크기  요소 수 156~328 → 64~252 (mobile)   패딩 조합 14~21 → 5~14
          타이포 조합 18~25 → 6~18            인라인 보유 74% → 65%
          ⚠ 상위 조합 **합집합은 늘었다** 36 → 50 — 덮개가 매 화면의 top 12 를
            점거해 **화면별 다양성을 가리고 있었다.** 줄어드는 쪽만 보면 놓친다
          ✅ #16(내부 overflow)은 14·5·3·3 그대로 — **처음부터 깨끗한 행이었다**
```

### ⛔ 넷째 — **hex 100건 중 74건이 오계수였다** (2026-08-06 · 같은 날 닫았다)

`token-audit.mjs` 는 CSS 변수 **정의**(`--x: #hex`)와 SVG 참조는 뺐는데
**`var(--토큰, #폴백)` 의 폴백 자리**는 안 뺐다. 그래서:

```
인쇄       하드코딩 hex 100건 · Generator 76 (전체의 76%)
실제       하드코딩 26건 · Generator 2 · 폴백 74
```

★ **폴백은 결함이 아니라 방어다** — 토큰이 안 실렸을 때 화면이 검게 죽지 않게 한다.
**그것을 결함으로 세면 잘 한 일이 벌점이 된다.** 그리고 이 저장소에서 가장 잘
토큰화된 파일이 **가장 나쁜 파일로 인쇄되고 있었다.**

⚠ **이 수 하나가 스킨 배치의 범위 판단을 통째로 떠받치고 있었다** —
*"Generator 가 개발 도구면 범위가 확 좁아진다"* 는 물음 자체가 76건 위에 서 있었다.
**세는 것이 틀리면 인쇄가 거짓말이 되고, 그 거짓말 위에서 계획이 선다.**

→ 폴백을 `hexAsVarFallback` 으로 **따로 센다**(0 으로 지우지 않는다 — 폴백이
줄어드는 것도 신호다). 재실행: `하드코딩 hex 26건 · ↳ var() 폴백 74건`.

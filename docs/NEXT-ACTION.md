```
1. 만들려는 화면이 프로토타입에 있는가?   grep 으로 마크업 위치를 찾는다
2. 있으면 → 읽고 옮긴다                    클래스·구조·인라인 스타일 그대로
3. 없으면 → 그때만 새로 그린다             그 사실을 커밋에 적는다
4. 검증에 육안 대조를 넣는다               빌드 통과는 이식 여부를 증명하지 않는다
5. 의도적으로 다르게 가면 근거를 대고 커밋에 적는다
6. 다르게 가기 전에 낡은 것과 일부러 그렇게 쓴 것을 가른다. 안 서면 묻는다
```

세 번의 위반이 각각 다른 형태였다.

1. **안 읽고 새로 그림** — 홈·사건 상세, 그리고 보고서
2. **읽다가 멈춤** — 사이드바만 읽고 `.main` 을 안 봐서 상단 헤더·우측 패널 누락
3. **저작 결정을 결함으로 오판** — 태그라인을 규칙 문장으로 바꿨다가 되돌림

그리고 **덜 옮기고 완성이라 말한 것**이 이번 지적이다. 표시만 토글·메모 탭.

상세는 `docs/MEMORY.md` §이식 규칙, `HANDOFF-TO-CODE.md` §8.1.

## 잊지 말 것 — 살아 있는 결정

1. **엔진이 게임 로직의 정본이다.** `npm run build` = 타입체크 + 사건 검증 + 앱 빌드.
2. **DC 툴 = 프로토타입 마스터.** 저장소 파일은 사본 — 직접 고치면 재export 때 사라진다.
   단 **읽는 것은 저장소 파일로 한다.** 이식에 DC 툴은 필요 없다.
3. **DC 잔여 5건이 저장소·배포본에만 적용돼 있다.** DC 툴을 여는 날
   `prototype/DC-SYNC-CHANGESET.md` 를 먼저 반영하고 export 할 것.
4. **태그라인은 프로토타입 그대로**(「모든 진술을 의심하라」). 규칙은 게임 안에서 전달한다.
5. **조사 예산은 `Case.budget`**(6). 프로토타입 하드코딩 5는 낡은 값이다.
6. **앱 클래스는 `nl-` 접두사.** Vector 가 `.detail`·`.chip` 을 이미 쓴다.
7. **런타임 LLM 0 / 게임은 최종 채점 전까지 완전 침묵.**
   채워진 공란은 전부 같게 생긴다. 잠긴 장은 번호만 남긴다.
8. **트릭은 이름표가 아니라 계약이다.** 원형을 늘리려면 `ARCHETYPES` 에 계약을 추가한다.

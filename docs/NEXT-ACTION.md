**★ 왕복 대조에 실패하면 안 내려받는다 ★** 쓴 것을 `parseCase` 로 다시 읽어 원본과
대조한다. 엔진이 `exit 1` 로 막는 자리다 — **반쯤 맞는 사건 파일이 커밋되는 것이
아무것도 안 나가는 것보다 나쁘다.**

> 이걸 하려고 **`schema.ts` 에서 `node:fs` 를 뺐다.** `loadCaseFile` 하나 때문에
> 파싱기 전체가 브라우저에 못 들어갔다 — `parseCase` 자체는 순수 함수인데 같은
> 파일에 산다는 이유로 같이 막혔다. 디스크를 읽는 일은 `load-case.ts` 로 갈랐다.
> `vite.config.ts` 의 *"Node 의존이 있는 `schema.ts` 는 번들에 안 들어온다"* 도
> 같이 고쳤다 — **이제 들어온다.**

**★ 붙이자마자 결함 하나를 물었다 ★** `applyProse` 가 지문·프롤로그는 `{ko}` 로
정규화하면서 **문단만 받은 그대로** 넣고 있었다. 앱이 두 형태를 다 렌더해서 안
드러났지만 `to-yaml.ts` 의 `txt()` 는 맨 문자열에서 `.ko` 를 찾는다 → **내보낸
YAML 의 문단이 전부 비어서 나갈 뻔했다.** 왕복 대조가 넣자마자 일했다.

> ④는 **verb 는 `fixture` 인데 kind 는 `location`** 이라 §9-4 의 **양방향 검사를 둘 다**
> 빠져나갔다. 고치자 이번엔 `resolveKeys` 가 선호 대상을 잃어 트릭의 현장 설비 조사가
> 엉뚱한 방으로 밀려났다(40건 중 29건). **하나를 바로잡으면 옆이 드러난다.**

**그리고 한 번 잘못 갔다가 되돌린 것 둘** — 현장 문에만 「잠긴 문」 이름표를 달았다가

> **§9-11 은 손으로 쓴 사건에는 안 문다.** 골든 케이스도 무고한 셋이 `t3:main` 로

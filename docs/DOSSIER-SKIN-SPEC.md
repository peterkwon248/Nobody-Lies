# 도시에 스킨 — 인계 지시서 (Claude Code)

> # ⏸ 대기 배치 — **감사·수리 후 착수**
>
> 착수 조건은 **UI 재균형 완결**(✅ 2026-08-05 `8e64fe5`)에 더해
> **기본 디자인 감사**(`docs/DESIGN-AUDIT-SPEC.md`) → **수리 배치**가 끝나는 것이다.
> 순서: 재균형 → 감사 → 수리 → **이 배치**.
>
> ⛳ **§5 축5(토큰 규율)가 이 배치의 선행 조건**이다 — 하드코딩 hex 가 박힌 자리는
> `--game-*` 폴백을 끼울 **토큰 자리가 없다.** 감사가 그 목록(§7이 예고한 그것)을
> 미리 만든다. **감사 전에 이 배치를 시작하면 자리가 없다는 것을 하나씩 발견하게 된다.**
>
> ⛳ **안착 경위** (2026-08-05): 챗에서 만들어졌으나 저장소로 오는 마지막 한 걸음에서
> 세 번 증발했다. 붙여넣기로 우회해 안착했다. **아직 한 줄도 실행되지 않았다.**

---

**배경**: 게임의 비주얼이 Vector DS(클린 툴 미학) 기반이라 정보 전달은 옳은데
**온도가 비어 있다** — 새벽의 산장과 분장실의 시신이 SaaS 대시보드와 같은 온도로
온다. 테스터들이 실제로 아쉬워한 지점이다 (`docs/PLAYTEST.md` 참조 — **이 작업
착수 전에 해당 피드백이 거기 기록돼 있어야 한다. 없으면 멈추고 요청**).

**사용자 결정 (2026-08-05)**:

- **방향**: 리스킨이 아니라 **토큰 별칭 층 한 겹** — "구조는 Linear, 온도는 사건 파일"
- **시점**: UI 재균형 배치(⓪~③)가 닫힌 직후. **같은 스타일 파일을 만지므로 병행
  금지** — 재균형이 아직 열려 있으면 이 지시서는 대기다.
- **선례**: Alpha Beyond `--grade-*` 별칭 층 · FlowBase `[data-surface]` 스코핑.
  **같은 수법의 세 번째 적용**이다.

## 1. 토큰 층 — 구조

```css
/* 게임 의미 토큰. Vector 토큰을 직접 마시던 자리에 별칭을 끼운다 */
:root[data-skin="dossier"] {
  --game-paper:        /* 지면 — 순백 대신 미색 서류 계열 */
  --game-paper-raised: /* 카드·패널 지면 */
  --game-ink:          /* 본문 먹색 */
  --game-ink-muted:    /* 보조 텍스트 */
  --game-accent:       /* 사건의 순간 — 잉크·핏빛 계열 단 하나 */
  --game-line:         /* 괘선·구분선 */
  --game-display-font: /* 제목 전용 세리프 */
}
```

- **폴백 필수**: 사용처는 전부 `var(--game-*, var(--기존토큰))` 꼴. 스킨이
  없으면(어트리뷰트 미부착) **현재 화면과 픽셀 단위로 동일**해야 한다 —
  **이것이 이 작업의 회귀 기준선이다.**
- 스코핑은 `data-skin` 어트리뷰트 하나. **JS 분기 금지** — 켜고 끄는 것은
  어트리뷰트 토글이지 코드 경로가 아니다.
- 구체 색값은 위 의미에 맞게 제안하되 **커밋 전에 스크린샷으로 사용자 확인** —
  색은 저작 판단이다.

## 2. 적용 자리 — 넷만, 도구 화면은 성역

```
① 지면            앱 배경 · 카드 지면. 온도의 8할이 여기다
② 제목 타이포     장 제목 · 사건명 · 인터루드 헤더만 세리프.
                  본문·격자·버튼·라벨은 현행 유지 — 도구 가독성은 Vector 가 옳다
③ 강조 액센트     확보 단어 하이라이트 · 범인 지목 · 보고서 제출 확인 —
                  "사건의 순간"에만. 상태색(성공·경고·오류)은 건드리지 않는다
④ 물성 소품 1~2   인터루드 카드의 미세한 종이 질감(CSS 그라디언트/노이즈,
                  이미지 에셋 금지) · 보고서 제출 시 도장/서명 느낌의 마이크로 모션 하나
```

**성역 (건드리면 안 되는 것)**: 격자 표 · 조사 목록 · 예산 표시 · 상태색 ·
본문 폰트 · 간격 체계. **도구 화면의 정보 밀도와 가독성이 이 게임의 실제 플레이
표면**이고, 스킨은 그 위가 아니라 **둘레에** 온도를 입힌다.

## 3. 제목 폰트 — 라이선스가 함정이다

- 후보는 **무료 상용 가능** 중에서만: Noto Serif KR · 마루 부리(네이버) ·
  KoPub 바탕. **조선일보명조류 신문 서체는 라이선스 확인 전 금지.**
- 한글 세리프 웹폰트는 무겁다 — **서브셋 필수**, 제목 전용이므로
  `font-display: swap` + 지연 로드. **본문에 절대 적용하지 않는다**(무게 폭발).
- 최종 서체 선택은 후보 2~3개 스크린샷으로 사용자에게.

## 4. A/B — 테스터가 판정한다

- 스킨 토글을 설정(또는 URL 파라미터 `?skin=dossier`)으로 노출한다.
  **기본값은 현행(스킨 off)** — 판정 전에 기본을 바꾸지 않는다.
- `docs/PLAYTEST.md` 에 질문 한 줄을 등재: **"분위기가 사건 같았나, 앱 같았나."**
  지인 절반씩 나눠 주는 것은 사용자 몫이다.
- 판정 후 기본값 변경/스킨 선택 상설화는 **별도 결정** — 이 배치의 범위 밖.

## 5. 검증

- **회귀 기준선**: 스킨 off 상태에서 375/768/1440 스크린샷이 재균형 배치 직후와
  동일. **스킨 작업이 기본 화면을 한 픽셀도 바꾸면 안 된다.**
- 스킨 on 스크린샷 같은 3폭 — 사용자 확인용.
- 게이트 15단 exit 0 (엔진 무접촉 예상이지만 전체 실행).
- **하드코딩 검사**: 이 배치에서 새로 적는 색·폰트 값은 전부 `--game-*` 토큰
  안에만 존재해야 한다. **컴포넌트에 hex 가 새로 생기면 그것이 회귀다** —
  `design-quality-gate` 의 기존 규칙 그대로.

## 6. 하지 않는 것

- 새 디자인 시스템 · 새 UI 라이브러리 · 이미지 에셋(질감 파일 포함)
- 일러스트 · 캐릭터 아트 (콘텐츠 제작이고 별도 결정)
- 코르크보드 · 빨간 실 · 필름 그레인 등 **클리셰 세트** — 액센트지 테마파크가 아니다
- 컴포넌트 구조 변경 · 도구 화면(§2 성역) 접촉
- 기본 스킨 변경 (A/B 판정 전)

## 7. 멈추고 물어볼 것

- 색 팔레트 확정 (스크린샷 2~3안)
- 제목 서체 확정 (후보 스크린샷)
- `--game-*` 를 끼우다 **폴백으로 표현 못 하는 자리**가 나올 때 (예: 지금 코드에
  하드코딩 hex 가 박혀 있어 토큰 자리가 없는 곳) — **그 목록을 모아 보고.
  하나씩 임기응변 금지**

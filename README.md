# 노바디 라이즈 · Nobody Lies

정지된 살인 사건 하나를 플레이어(무명의 수사관)가 **진술 정독 → 제한된 조사 → 보고서 공란 채우기**로 푸는 추리 게임.

계보는 Return of the Obra Dinn → The Case of the Golden Idol. 차이는 사건을 논리 검증기로 검사해 자동 생성할 수 있다는 것.

> 무고한 사람은 거짓말하지 않는다. 다만 자기 비밀은 말하지 않는다.
> 그리고 제목 자체가 거짓이다 — 다섯 중 하나는 거짓말을 한다.

**현재 단계: 설계 완료 · 프로토타입 완성 · 플레이테스트 이전 · 프로덕션 코드 0줄**

---

## 시작하기

```bash
npm install
npm run build
```

`build`는 앱 빌드가 아니라 **사건 검증**이다. `engine` 타입체크 + 산장 사건 논리 검사를 돌리고, 검증에 실패하면 exit 1로 끝난다. 프로덕션 코드가 없는 지금 단계에서 가장 의미 있는 게이트가 "사건이 여전히 논리적으로 성립하는가"이기 때문이다.

검증 결과만 보려면:

```bash
npm run verify
```

프로토타입을 플레이해보려면 `prototype/playtest/` 안의 단일 HTML 파일을 브라우저로 연다. (상황판 뷰가 빠져 있다 — `docs/MEMORY.md` 참조)

---

## 구조

| | |
|---|---|
| `docs/` | 설계 정본. **`MEMORY.md`부터 읽을 것** |
| `engine/` | 사건 검증기 (TypeScript). 프로덕션 앱의 **이식 원본이지 앱 코드가 아니다** |
| `prototype/` | Claude Design 프로토타입. 거의 모든 화면이 동작하지만 배포 대상이 아니다 |
| `design/` | 아이콘 탐색 · 비교 스크랩 · 세션 캡처 |
| `app/` | 프로덕션. 아직 없음 |

---

## 읽는 순서

1. **`docs/MEMORY.md`** — 현재 상태, 절대 규칙, 문서 신뢰도 경고, 미해결 목록. 다른 문서를 읽기 전에 이걸 먼저 봐야 한다. **설계 문서에 죽은 절이 여럿 있고 MEMORY.md에만 무엇이 무엇을 이겼는지 정리돼 있다.**
2. `docs/HANDOFF-TO-CODE.md` — 저장소 분리·스키마·판정·구현 범위
3. `docs/design-brief.md` — 마스터 스펙 (화면·상태·원칙)
4. `docs/SYSTEM-DECISIONS.md` — 채점·경쟁·확장·LLM·수익화
5. `engine/templates/README.md` — 사건 저작법

---

## 이 게임이 하지 않는 것

> 게임이 플레이어의 판단에 대해 하는 말은 최종 채점 하나뿐이다. 그 전까지 완전한 침묵.

실시간 채점 없음. 모순 경고 없음. 게임이 하는 텍스트 강조 없음. 조사 추천·힌트 없음. 결정적 단서와 레드 헤링이 완전히 동일하게 생겨야 한다.

이 규칙은 개발 중 일곱 차례 다른 형태로 재발했다. 전부 "친절한 UI의 기본값"에서 나온다. 새 기능을 만들 때마다 확인할 것 — **이 화면이 플레이어가 내려야 할 결론을 미리 말하고 있는가?**

그리고 **런타임 LLM은 0이다.** 예외 없음.

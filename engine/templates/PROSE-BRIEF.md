# 산문 의뢰 서식 (Claude 웹에 붙여 넣는 것)

> **이것은 2단계 중 2단계다.** 논리 골격은 `CASE-BRIEF.md` 로 먼저 받는다.
>
> ```
> ④ CASE-BRIEF   논리 골격 + actions[].result + report  →  npm run build  ← 관문
> ② 이 파일       진술·지문·프롤로그·장 서사·terms·record  →  npm run build
> ```
>
> ⚠️ **`actions[].result` 는 ④가 쓴다.** 검증기 §9-8e 가 결과문 없는 조사를
> 오류로 막아서, 논리만 있는 YAML 은 애초에 통과하지 못한다(2026-07-29 실측).
> 손으로 쓴 사건에 결과문을 뒤늦게 채울 때만 이 서식으로 의뢰한다.
>
> **쓰는 법.** 아래 「⬇ 여기서부터 복사」 이후를 통째로 복사 → `{{ }}` 자리를 채움 →
> Claude(웹)에 붙여 넣음 → 받은 YAML을 `engine/cases/<사건>.yaml` 에 넣음 →
> **`npm run build` 로 검사**. 검증기가 반려하면 반려 사유를 그대로 다시 붙여 넣으면 된다.
>
> **이 서식이 곧 ②산문가(빌드타임 LLM)의 명세다.** 여기서 잘 도는 프롬프트가
> 그대로 스크립트가 된다 — 서식을 고치면 명세를 고치는 것이다.

⬇ 여기서부터 복사

당신은 추리 게임 「노바디 라이즈」의 **산문가**입니다. 사건의 **논리는 이미 확정돼
있고**, 당신은 거기에 문장만 입힙니다. 논리를 바꾸거나 새 사실을 만들지 마세요.

## 절대 규칙 — 어기면 게임이 망가집니다

이 게임의 상품은 **「내가 알아냈다」는 감각**입니다. 아래는 예외가 없습니다.

1. **판정하지 않습니다.** 「따라서 범인이다」·「수상하다」·「중요한 단서다」 금지.
   당신은 **본 것만** 적고, 뜻은 플레이어가 붙입니다.
2. **해석 단어를 쓰지 않습니다.** 「위조」·「가명」·「밀폐」·「위장」처럼 **결론이
   박힌 명사**를 쓰지 마세요. 「필체가 원고와 달랐다」는 되고 「위조된 유서」는 안 됩니다.
3. **유용도를 드러내지 않습니다.** 결정적 단서와 레드 헤링이 **같은 온도**로 쓰여야
   합니다. 중요한 것을 길게 쓰거나 강조하면 그게 정답 누설입니다.
4. **새 사실 0.** 주어진 데이터에 없는 정보를 문장으로 만들지 마세요. 시각·수량·
   이름·관계를 지어내면 검증기가 잡거나, 더 나쁘게는 안 잡히고 게임이 어긋납니다.
5. **3인칭 관찰**로 씁니다. 서술자는 수사 기록의 목소리입니다.

## 층별 규칙

| 무엇 | 규칙 |
|---|---|
| **프롤로그** | **새 정보 0.** 브리핑·진술에 이미 있는 것만. 분위기용 한 줄이 조사로 얻어야 할 것을 무료로 풀면 난이도가 무너집니다 |
| **진술 원문** | 무고한 사람은 **진실을 말하되 자기 비밀은 숨깁니다.** 범인만 거짓말합니다. 다섯 사람의 **말투가 서로 달라야** 하되, 불안·초조를 한 사람에게만 주면 그게 범인 표시가 됩니다 |
| **지문**(진술 앞뒤) | **전원이 갖거나 전원이 없거나.** 넷은 담담한데 하나만 떨면 지문이 곧 범인 표시입니다 |
| **조사 결과문** | 그 조사가 **실제로 주는 것만** 말합니다. 안 주는 물증·단어를 언급하면 플레이어가 문장에서 보고 은행에서 못 찾습니다 |
| **장 서사**(장 완성 시) | **전부 쓰거나 전부 비우거나.** 일부만 있으면 서사의 유무가 곧 유용도 신호입니다. 장 제목이 말하는 것 **이상을 말하지 않습니다** |
| **확보 단어 기록** | 「무엇이었나」만. 「무엇을 뜻하나」 금지 |

## 이 사건의 논리 (건드리지 마세요)

```yaml
{{ 여기에 engine/cases/<사건>.yaml 의 논리 부분을 붙여넣기.
   최소한: incident · slots · locations · people(이름·나이·직업) ·
   evidence(id·description·record) · actions(id·label·verb·gives·yield) ·
   chapters(title·blanks) · trick · reveals(trigger·addClaims 대상) }}
```

> ⚠️ **짝을 반드시 같이 붙이세요.** 의뢰하는 자리와 **같은 동사·같은 `yield`** 의
> 이미 쓰인 항목을 함께 넣습니다. 위 절대 규칙 3(「같은 온도로 쓴다」)은 **맞출
> 대상이 브리프 안에 있어야만 지킬 수 있습니다** — 없으면 산문가는 온도를 혼자
> 정하고, 한쪽이 길어지는 순간 그게 유용도 표시가 됩니다.
>
> 사건 전체를 붙일 필요는 없습니다. 조사 하나를 의뢰한다면 **그 조사 + 짝이 되는
> 조사 + 대상 인물 + 관련 reveal + 확보 단어 풀(금지 목록)** 이면 충분합니다.

## 채워야 할 자리

{{ 아래에서 필요한 것만 남기고 나머지는 지우세요 }}

- `prologue` — 4줄 안팎
- `people[].statement.paragraphs` — 인물당 10~14문단
- `people[].statement.gesture` — `{pre, post}` (전원 또는 전무)
- `actions[].result` — `{title, body}` (물증을 주는 조사는 **반드시**)
- `evidence[].record` — 물증 카드의 기록. **결과문과 한 벌이다** — 조사 산문을
  의뢰하면서 이걸 빼면 그 조사가 준 물증이 카드에 이름만 남는다
- `actions[].clues` — `{person, slot, text}` 프로필 카드 한 줄
- `terms[].source` · `terms[].note` — 확보 단어 사전
- `reveals[].narration` — 장 완성 서사 (전부 또는 전무)
- `reveals[].addClaims[].content` — 새로 열리는 주장

## 출력 형식

**YAML 조각만** 주세요. 설명·서론·「여기 있습니다」 없이 바로 코드블록으로.
`{ ko: ..., en: ... }` 형식이 필요한 자리는 둘 다 채우고, 영문이 아직 없으면
`ko` 만 쓰세요.

⚠️ **flow mapping(`{ }`) 안에 쉼표가 들어가는 문장은 반드시 따옴표로 감싸세요.**
`{ ko: 외상은 없고, 혈중 농도가 높았다. }` → **여기서 잘립니다.** 파서는 아무 말도
하지 않습니다. 이 결함이 이 프로젝트에서 세 번 나왔습니다.

```yaml
# 예시
terms:
  - word: 유서
    source: { ko: 소지품 검사 · 문세라, en: Belongings · Se-ra }
    note: { ko: "완성되지 않은 초안이었고, 필체가 원고와 달랐다.", en: "..." }

actions:
  - id: a_sakura
    result:
      title: { ko: 유서 초안과 금고 열쇠, en: Draft note & safe key }
      body:  { ko: "세라의 짐에서 윤다인 명의 유서 초안과 금고 열쇠가 나왔다." }
    clues:
      - { person: sakura, slot: means, text: 위장용 유서 초안·금고 열쇠 }
```

## 합격 기준 (기계가 검사합니다)

받은 YAML은 `npm run build` 의 검증기를 지나야 합니다. 걸리는 것들:

- 확보 단어인데 **얻을 길이 없다** (씨앗도 아니고 주는 조사도 없다) → 오류
- **프롤로그가 조사로 얻을 단어를 말한다** → 오류
- 조사 결과문/서사가 **그 조사가 주지 않는 단어를 말한다** → 경고
- **지문이 일부 인물에게만 있다** → 오류
- **현장 서술이 씨앗 밖 단어를 말한다** → 오류
- **장 완성 공개 중 일부만 서사를 갖는다** → 오류
- **물증을 주는데 결과문이 없다** → 오류 *(9-8e)*
- **아무도 쓰지 않는 물증** — fact·트릭·확보 단어·기록 어디에도 없다 → 경고 *(9-8f)*
- **진술 길이가 한쪽으로 쏠린다** — 가장 긴 것이 가장 짧은 것의 **2배를 넘고 차이가
  2문단 이상** → 오류 *(9-9)*. 위 절대 규칙 3을 기계가 재는 자리다. 「같은 온도」는
  문장의 결만이 아니라 **길이**이기도 하다

> ⚠️ **이 목록은 검증기보다 낡을 수 있습니다.** 위 둘은 서식을 처음 실사용한 날
> (2026-07-28) 검사를 더하면서 함께 적은 것입니다. **`verifier.ts` 에 검사를
> 더하면 이 절도 같이 고칩니다** — 명세가 뒤처지면 산문가가 통과할 수 없는 것을
> 만들어 옵니다.

반려되면 **오류 문구를 그대로 다시 붙여 넣고 그 부분만 고쳐 달라고** 하세요.

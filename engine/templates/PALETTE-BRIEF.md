# 세계 팔레트 의뢰 서식 (Claude 웹에 붙여 넣는 것)

> **이것이 주력 경로다.** LLM은 **어휘만** 만들고, 사건의 논리(범인·트릭·격자·
> 물증·조사·공란·예산)는 전부 코드가 만든다.
>
> ```
> PALETTE-BRIEF  →  palette.json  →  generateCase(seed, palette)  →  verify  →  사건 N개
>     LLM 1회                            코드                        관문
> ```
>
> **LLM 호출은 사건 수가 아니라 세계 수에 비례한다.** 팔레트 하나로 seed 만
> 바꾸면 사건이 계속 나오고, 뼈대가 검증된 것에서 나오므로 **통과율이 구조적으로
> 100%다**(2026-07-29 실측: 200/200).
>
> 비교 — `CASE-BRIEF.md` 는 LLM에게 논리까지 시킨다. 골든 케이스를 손으로 늘릴
> 때나 팔레트가 못 만드는 특이한 사건에만 쓴다.

## 쓰는 법

```bash
# 1. 아래를 복사해 Claude(웹)에 붙여 넣고 JSON 을 받는다
# 2. engine/templates/my-palette.json 으로 저장
# 3. 돌린다
npm run verify -w engine -- --generate 40 --palette templates/my-palette.json

#    장 수와 난이도를 고르려면 (난이도는 선호 순서)
npm run verify -w engine -- --generate 40 --palette templates/my-palette.json --chapters 5 --want normal,hard
```

### 마음에 드는 사건이 나오면

```bash
# 앱에서 바로 열어보기 — /?case=gen-7
npm run verify -w engine -- --generate 10 --palette templates/my-palette.json --emit ../app/public/cases

# 저작 가능한 YAML 로 뽑기 (왕복 대조가 붙는다)
npm run verify -w engine -- --generate 1 --palette templates/my-palette.json --emit ../out --yaml
```

**YAML 로 뽑는 이유**: 산문을 입히는 순간 그것은 생성물이 아니라 **저작물**이다.
사람이 고치고 git 이 추적하는 형태로 남아야 한다.

```
팔레트 → 생성 → YAML 방출 → PROSE-BRIEF 로 산문 → engine/cases/ 에 커밋
```

같은 팔레트 + 같은 seed 는 **항상 같은 사건**이다(결정론적). 그래서 seed 만
적어두면 언제든 다시 만들어진다.

예시: [`palette-example.json`](palette-example.json) (심야 라디오 방송국)

⬇ 여기서부터 복사

당신은 추리 게임 「노바디 라이즈」의 **세계 설계자**입니다.
하나의 무대에 쓸 **어휘 목록**을 JSON으로 만들어 주세요.

## 가장 중요한 것

**당신은 사건을 만들지 않습니다.** 범인·트릭·동선·물증·정답은 전부 프로그램이
정합니다. 당신이 주는 것은 **그 프로그램이 골라 쓸 단어들**입니다.

그래서 **어느 것이 정답에 쓰일지 당신도 모릅니다.** 이것이 규칙 하나로 이어집니다:

> **목록 안의 항목은 전부 같은 무게여야 합니다.**
> 「이게 진짜 흉기 같다」거나 「이 동기가 제일 그럴듯하다」가 티나면, 프로그램이
> 무엇을 고르든 플레이어는 목록만 보고 답을 좁힙니다. 그게 정답 누설입니다.

## 채울 것

```json
{
  "setting": "무대 이름 (예: 심야 라디오 방송국)",
  "names":   ["8개 이상 — 한국식 이름. 실존 인물 금지"],
  "jobs":    ["6개 안팎 — 그 무대에 있을 법한 직업"],
  "items":   ["6개 안팎 — 그 무대의 일상 물건"],
  "motives": [{ "label":      "4개 안팎 — 짧은 명사구. 여기만 문장 금지",
                "background": "무엇이 쌓였나",
                "trigger":    "그날 무엇이 터졌나",
                "resolve":    "왜 그 방법이었나" }],
  "rooms":   ["8개 — 부지 안의 다른 방들. 이름만 줘도 되고, 성질을 붙여도 됩니다",
              { "name": "암실", "noWindow": true, "fixture": "인화기" }],
  "records": ["8개 — 뒤지면 나올 기록·흔적. 장마다 하나씩 쓰입니다"],
  "secrets": ["6개 이상 — 각자 감추는, 사건과 무관한 창피한 사실",
              "「…했다는 것」처럼 명사구로 끝내면 가장 깔끔합니다"],
  "openers": ["6개 이상 — 진술을 여는 말버릇"],
  "gestures": [{ "pre": "진술 앞의 몸짓 한 줄", "post": "진술 뒤의 몸짓 한 줄" }],
  "places":  { "hall": "사람들이 모이는 곳",
               "room": { "name": "사건 현장", "fixture": "그곳의 설비 이름" },
               "approach": "부지 안의 실외 — 건물과 바깥 사이",
               "away": "부지 밖" },
  "times":   { "t0": "사건 전", "t1": "사망 추정 구간", "t2": "발견",
               "window": ["구간을 쪼갤 때만 — 칸마다 하나씩"] }
}
```

> ★ **용의자는 언제나 5명입니다** ★ 팔레트가 정하는 값이 아닙니다.
> 이름을 몇 개 주든 프로그램이 다섯을 고릅니다.

### 항목별 주의

| | |
|---|---|
| `names` | 8개 이상. 그중 **다섯이 용의자**, 하나가 **기록에 남은 이름**으로 쓰입니다. 성별·연령대가 섞이게 |
| `rooms` | **8개.** 「부엌」·「서재」·「지하실」처럼 부지 안의 다른 방. 대부분 뒤져도 아무것도 안 나오지만 **빈손도 배제 정보**이고, 조사 대상이 예산의 3배 이상이어야 선택이 소거가 아니라 판단이 됩니다. `places` 의 셋과 겹치지 않게. 모자라면 프로그램이 채웁니다.<br>**이름만 줘도 되고**, 아래 성질을 붙이면 평면도가 그만큼 그럴듯해집니다 — `{ "name": "암실", "noWindow": true, "fixture": "인화기" }`<br>⛔ **좌표는 주지 마세요.** 배치·문·창은 프로그램이 격자에서 계산합니다. 여기서 받는 것은 **프로그램이 알 수 없는 세계 지식**뿐입니다 |
| ↳ `noWindow` | **창이 날 수 없는 방.** 암실·수장고·지하실처럼 빛이나 외기를 막는 곳. 안 적으면 바깥벽에 창이 납니다 — 암실에 창이 뚫리면 그 세계가 거짓말이 됩니다 |
| ↳ `fixture` | 그 방에서 **눌러볼 만한 설비** 이름(가마 · 인화기 · 보일러 · 배전반). 도면 위의 점이 되고 「고정물 조사」의 대상이 됩니다. 당신은 어느 방이 현장이 될지 모르므로 이름이 사건을 가리킬 수 없습니다. **방에 실제로 있을 법한 것**만 적으세요. ⚠ **되도록 전부 채우세요** — 안 주면 「○○ 설비 확인」으로 때우는데, 프로그램이 만드는 트릭 조사는 **언제나 물건 이름**(「잠금장치 조사」)이라 **모양이 갈리는 쪽이 곧 쓸모 있는 쪽**이 됩니다. 빠뜨려도 사건은 만들어지지만 경고가 뜹니다 |
| `records` | **8개.** 「출입 기록」·「빌린 열쇠」처럼 뒤지면 나올 **기록·흔적**. 보고서의 장마다 하나씩 쓰여 그 장을 여는 열쇠가 됩니다. ⚠ **`items` 와 낱말이 겹치면 안 됩니다** — 겹치면 조사 결과문이 「주지 않는 단어를 말한다」로 검증기에 걸립니다 |
| `secrets` | **6개 이상.** 이 게임의 제목이 곧 규칙입니다 — *무고한 사람은 거짓말하지 않는다, 다만 자기 비밀은 말하지 않는다.* 다섯 명이 **하나씩** 받아 「그건 사실이지만 이 일과는 상관없다, 더는 말하지 않겠다」고 말합니다 — **내용은 화면에 그대로 나옵니다**(감추는 것은 그 *이상*이지 그 사실 자체가 아닙니다). 그러니 **읽어서 말이 되는 한 문장**으로 써 주세요. 틀은 다섯 사람이 서로 다르게 붙습니다. ⚠ **살인과 이어지면 안 됩니다.** 「피해자와 다퉜다」 같은 것을 주면 무고한 사람이 용의자가 되고 논리가 무너집니다. 「빌린 돈을 못 갚았다」·「이력서를 부풀렸다」처럼 **창피하지만 무관한** 것이어야 합니다. ⚠ **`items`·`records` 와 낱말이 겹치면 안 됩니다** — 진술이 조사로 얻을 것을 먼저 말하면 검증기 §9-10 이 잡습니다 |
| `openers` | **6개 이상.** 「몇 번을 말씀드렸지만,」·「글쎄요,」처럼 진술을 여는 **말버릇**. 사람마다 다른 하나를 받아 다섯이 구분됩니다. ⚠ **길이를 비슷하게** 맞추세요 — 한 사람만 길어지면 그게 유용도 표시가 되고 §9-9 가 오류로 잡습니다 |
| `gestures` | **6쌍 이상.** 진술 앞뒤에 기울임체로 붙는 **몸짓** — 「빈 잔을 두 손으로 감싸 쥔 채였다」 / 「말끝이 조금 흐려졌다」. 다섯 명이 하나씩 받습니다. ⚠⚠ **다섯이 같은 온도여야 합니다 — 이 칸의 전부가 이것입니다.** 넷은 담담한데 하나만 떨면 지문이 곧 범인 표시이고(§9-1 이 오류로 잡습니다), **반대도 같습니다** — 넷이 안절부절인데 하나만 침착해도 그 하나가 튑니다. **누가 범인인지 모르는 채로 읽어도 고르게 불편하게** 쓰세요. ⚠ **이름을 쓰지 마세요** — 진술 카드에 이미 있습니다. ⚠ `items`·`records` 와 낱말이 겹치면 안 됩니다 (`secrets` 와 같은 이유) |
| `jobs` | 무대와 관계가 있어야 합니다. 「그 사람이 왜 거기 있었나」가 설명돼야 하니까요 |
| `items` | **판정어 금지.** 「흉기」·「독극물」 같은 이름을 쓰지 마세요. 「보온병」·「큐카드」처럼 **그냥 물건**이어야 합니다 |
| `motives` | **이름표 하나 + 인과 세 칸.** ⛔ **`label` 에만 문장 금지가 걸립니다** — 「채무 관계」·「자리 다툼」 정도의 짧은 명사구여야 합니다. 그 자리가 보고서 「동기」 공란의 **정답**이자 **확보 단어**여서, 문장이 되면 드롭다운과 단어 은행이 깨집니다.<br>**나머지 세 칸은 반대로 문장으로 쓰세요** — `background`(무엇이 쌓였나) · `trigger`(그날 무엇이 터졌나) · `resolve`(왜 그 방법이었나). 엔딩 1막의 마지막 비트가 이 셋을 그대로 읽습니다. 세 칸이 없으면 「이유는 기록에 「채무 관계」라고 남았다」 한 줄로 끝납니다 — 그것이 테스터가 *"딱딱한 진실 나열"* 이라고 부른 그 자리입니다.<br>⚠ **`resolve` 의 문형을 넷 다 다르게** 하세요. 같은 꼴로 넷을 쓰면 사건을 여러 개 만든 사람에게 합창으로 들립니다.<br>⚠ **셋 중 하나만 비우면 안 됩니다** — 검증기가 막습니다(반쪽이면 문장에 마침표만 남습니다). 넷 다 안 쓰고 `["채무 관계", …]` 처럼 **맨 문자열로 줘도 됩니다**. 그때는 폴백 한 줄로 갑니다 |
| `places` | `hall`·`room`·`away` **셋은 필수**, `approach` 는 선택입니다(안 주면 「진입로」). `room` 이 현장이고, `approach` 는 **부지 안의 실외** — 건물과 바깥 사이라 「걸어서 2분」이 알리바이의 재료가 됩니다 |
| ↳ 설비 이름 | **`rooms` 와 같은 규약입니다** — 맨 문자열이면 이름만, `{ "name": …, "fixture": … }` 면 설비 이름까지. 네 곳도 도면 위에 점을 하나씩 갖습니다. 산장은 거실에 **금고**가 있고 그것이 유서의 경로입니다 — 모이는 곳에 이름 있는 설비가 있으면 조사가 뜻을 갖습니다. **일부만 줘도 됩니다.** ⚠ **`rooms` 의 `fixture` 와 낱말이 겹치면 안 됩니다** — 도면에 같은 이름표가 둘 뜹니다(전시실이 둘이면 「전시 진열장」도 둘이 되는 식) |
| `times` | 가운데(`t1`)가 사망 추정 구간입니다. 셋이 **시간순**이어야 합니다. ⚠⚠ **어휘 중 가장 비싼 자리입니다** — `times` 는 **다섯 사람의 진술마다 반복 인용**되므로(「…에는 …에 있었습니다」) 한 낱말이 어색하면 **진술 전부가 흐려집니다.** `rooms` 처럼 옆에 설명이 붙는 자리가 아니니 아래 은어 절을 특히 여기에 적용하세요 |
| ↳ `window` | **선택.** 사망 추정 구간을 **두 칸 이상으로 쪼갤 때만** 씁니다(만들 때 「사망 구간 칸 수」를 2나 3으로 둔 경우). 칸마다 이름표가 하나씩 필요한데 `t1` 은 하나뿐이라서입니다 — `["첫 순찰", "두 번째 순찰"]` 처럼 **칸 수만큼** 적으세요. 안 적으면 프로그램이 `t1` 에 「(전반)·(후반)」을 붙여 채우는데 **그건 기계가 지은 어휘**이고 하필 가장 비싼 자리라 경고가 뜹니다. 한 칸이면 아예 필요 없습니다 |

### ⚠ 업계 은어를 쓰지 마세요 — 플레이어는 그 세계 사람이 아닙니다

무대에 정통할수록 **그 바닥에서만 쓰는 말**이 섞여 들어옵니다. 실제로
레지던시 팔레트가 `t0` 를 **「저녁 합평이 끝난 직후」**로 썼는데, 합평(서로의 작업을
비평하는 자리)을 **이 게임을 만든 사람도 몰랐습니다.** 테스터는 더 모릅니다.

**시간대 이름은 특히 위험합니다** — 진술마다 반복해서 인용되므로, 한 낱말을 모르면
**다섯 사람의 진술이 전부 흐려집니다.**

```
✗ 저녁 합평이 끝난 직후      ✓ 저녁 모임이 끝난 직후
✗ 마감 대기 중              ✓ 밤 10시부터 자정 사이
```

기준: **그 직업이 아닌 사람이 사전 없이 읽어서 뜻이 서는가.** 안 서면 한 칸 낮춥니다.
질감은 `rooms`·`items`·`records` 로 내세요 — 거기서는 「가마실」·「반출 신청서」처럼
**옆에 설명이 붙는 자리**라 모르는 낱말이어도 뜻이 섭니다.

### `places.room` 은 다섯 트릭을 전부 견뎌야 합니다

프로그램이 **위장 자살 · 밀실 · 알리바이 위조 · 시신 이동 · 지연 장치** 중
하나를 고릅니다. 어느 것이 걸릴지 모르므로 `room` 은 이런 곳이어야 합니다:

- **문과 창이 있는 실내** (밀실·위장 자살이 창턱과 잠금장치를 씁니다)
- **`hall` 에서 걸어서 갈 수 있는 곳** (시신 이동이 끌린 자국을 씁니다)
- **물건을 미리 놓아둘 수 있는 곳** (지연 장치가 씁니다)

야외·차량·엘리베이터처럼 이 중 하나가 성립하지 않는 곳은 피하세요.

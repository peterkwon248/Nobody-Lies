# 검열 의뢰 서식 (⑤검열관 · 챗봇에 붙여 넣는 것)

> **이것은 다른 브리프 넷과 방향이 반대다.** `CASE`·`PALETTE`·`PROSE`·`STATEMENT` 는
> **만들어 달라**고 하지만, 이것은 **이미 있는 것을 읽고 흠을 잡아 달라**고 한다.
>
> ```
> 코드   검열 브리프를 만든다     산문 + 그것이 어겨선 안 될 데이터를 나란히
> 사람   챗봇에 붙여넣는다        §8 — 앱은 AI API 를 쓰지 않는다
> LLM    「경고」 목록을 낸다      의미 이해. 여기만 LLM 이다
> 코드   경고를 받아 판정한다      npm run censor -- <사건> --judge <응답>
> ```
>
> ⚠️ **LLM 은 판정하지 않는다** (`MANIFESTO §14`). 낸 경고는 전부 **코드가 검산**한다 —
> 인용한 문장이 실물에 없으면 **아무리 그럴듯해도 기각**된다. 그래서 아래 출력 서식이
> `quote` 를 **원문 그대로** 요구한다. 요약하거나 고쳐 쓰면 기각된다.
>
> **쓰는 법**
> ```bash
> npm run censor -w engine -- cases/mountain-lodge.yaml        # 브리프가 나온다
> # → 통째로 복사해서 챗봇에 붙여넣기 → 받은 YAML 을 파일로 저장
> npm run censor -w engine -- cases/mountain-lodge.yaml --judge resp.yaml
> ```
>
> **왜 이것만 남았나.** 상용화 게이트 18칸 중 13칸은 결정론적 검사가 닫았다.
> 남은 5칸(보고서 × 모순 · 장 전환 서사 ×2 · 장 인터루드 ×2)은 **글자에 시각·장소
> 이름표가 없어서**(0/1037 · 1/176 · 0/218) 대조할 닻이 없다. 남는 벡터는
> *"그날 아침 도착했다"* 같은 **자연어 사건 주장**뿐이고 그것만 여기서 본다.

⬇ 여기서부터 복사

당신은 추리 게임 「노바디 라이즈」의 **검열관**입니다. 사건은 이미 완성돼 있습니다.
당신의 일은 **문장을 고치는 것이 아니라, 흠을 찾아 보고하는 것**입니다.

**아무것도 다시 쓰지 마세요. 제안도 하지 마세요.** 경고만 냅니다.

## 무엇을 찾나 — 둘뿐입니다

### ① 누설 (`leak`) — 조사하지 않아도 답이 나온다

이 게임의 상품은 **「내가 알아냈다」는 감각**입니다. 아래 산문이 조사 없이
범인·트릭·사인을 알려주면 상품이 사라집니다.

- 범인 한 사람만 이름이 나온다
- 조사해야 얻을 수 있는 것을 문장이 먼저 말한다
- 「가장 수상한」·「이상하게도」처럼 **어디를 보라고 가리키는 말**

### ② 모순 (`contradiction`) — 문장이 데이터와 다른 말을 한다

**이것이 이 검열의 핵심입니다.** 아래 §사실 표와 §검열 대상을 **한 줄씩 대조**하세요.

특히 **사건을 단언하는 문장**을 의심하세요. 예:

```
"그날 아침, 가장 먼저 도착한 두 사람이 …"
   → 사실 표에 「도착」이라는 사건이 있나? 아침에 오는 사람이 있나?
"방 안의 일은 정리됐다"
   → 그 장에서 실제로 정리된 것이 방 안의 일인가?
```

⚠️ **시각·장소 이름이 안 나온다고 안전한 게 아닙니다.** 「아침」·「먼저」·「뒤이어」
같은 말이 **시간 관계를 주장**합니다. 그 주장이 사실 표와 맞는지 보세요.

## 무엇을 찾지 **않나**

- 문장이 좋은가 · 재미있는가 · 자연스러운가 → **보지 마세요.** 취향은 검열이 아닙니다
- 맞춤법·문체 → 보지 마세요
- 「이 단서가 너무 어렵다/쉽다」 → 난이도는 사람이 정합니다

## 사실 표 — 산문이 여기에 어긋나면 안 됩니다

```
{{FACTS}}
```

## 검열 대상 — 이 문장들만 봅니다

```
{{PASSAGES}}
```

## 낼 것 — 이 YAML **하나만** 내세요

```yaml
warnings:
  - where: prologue[2]          # 위 [대괄호] 안의 자리 이름을 그대로
    kind: contradiction          # leak 또는 contradiction 만
    quote: "그날 아침, 가장 먼저 도착한 두 사람이 창밖으로 새어 나오는 연기를 보았다."
    why: 사실 표에 도착 사건이 없다. 다섯은 전날 밤부터 건물 안에 있다
```

**규칙**

1. `quote` 는 **원문을 글자 그대로** 옮깁니다. 요약·수정하면 코드가 기각합니다
2. `where` 는 위 대괄호 안의 이름을 **그대로** 씁니다
3. 흠이 없으면 `warnings: []` 를 냅니다. **없는 흠을 만들지 마세요**
4. 확신이 없으면 **내지 마세요.** 기각될 경고보다 놓친 경고가 낫습니다 —
   이 검열은 여러 번 돌릴 수 있습니다

## 관리자용 (복사 구간 밖이다)

**코드가 검산하는 것 셋** (`censor.ts` §judge):

```
ⓐ 인용한 문장이 실제로 그 자리에 있나   없으면 지어낸 것 → 기각
ⓑ 가리킨 자리가 실재하나                 없는 채널 → 기각
ⓒ 등급이 아는 것인가                     leak · contradiction 외 → 기각
```

ⓐ가 **환각 차단**이다. LLM 이 그럴듯한 경고를 지어내도 원문에 없으면 판정에 못 든다.
`MANIFESTO §14`(게임 판정은 코드) 를 검열 층에서 지키는 방법이고, 이것이 없으면
*"LLM 이 규칙을 결정하지 않는다"* 가 말뿐이 된다.

⛳ **재현 테스트가 있다** — `closing-theater.yaml` 은 **프롤로그 불일치를 일부러
남긴** 사건이다(워크로그 Blockers). 이 브리프가 그것을 잡아야 한다.

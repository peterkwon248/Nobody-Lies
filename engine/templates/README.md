# 사건 만들기

## 세 갈래 — 무엇을 LLM에게 시키나

| | 서식 | LLM이 만드는 것 | 언제 |
|---|---|---|---|
| **팔레트** ★ | `PALETTE-BRIEF.md` | **어휘만** | 싸게 많이. LLM 1회 = 사건 N개 |
| 사건 통째 | `CASE-BRIEF.md` → `PROSE-BRIEF.md` | 논리 + 산문 | 팔레트가 못 만드는 특이한 사건 |
| 손으로 | 이 문서 + `case-template.yaml` | — | 정성껏 만드는 골든 케이스 |

**주력은 팔레트다.** 논리를 코드가 만들면 뼈대가 검증된 것에서만 나오므로
통과율이 구조적으로 100%이고(2026-07-29 실측 200/200), LLM 호출이 사건 수가
아니라 **세계 수**에 비례한다.

```bash
npm run verify -w engine -- --generate 40 --palette templates/palette-example.json
```

셋 다 **이 문서의 작법이 그대로 적용된다.** 아래를 먼저 읽어라 — 특히
「판별자는 기회다」와 「작가가 쓰지 않는 것」은 생성기가 코드로 구현한 것이다.

---

## 두 단계로 나눈다

아이디어가 떠올랐을 때 바로 템플릿을 여는 건 비효율적이다. 200줄짜리 폼 앞에서 대부분 막힌다.

**먼저 스케치, 통과하면 템플릿.**

---

## 1단계 · 스케치 (5분)

아래 여섯 줄만 채운다. 이것만으로 사건이 성립하는지 판단할 수 있다.

```
무대       :
피해자     :
숨은 범죄  :
범인       :   (숨은 범죄에서의 역할:        )
트릭       :
트릭의 허점:
```

### 스케치 통과 조건

**하나. 동기가 숨은 범죄에서 나오는가.**
살인의 동기가 L1과 무관하면 이 게임 구조가 아니다. 치정이나 원한만으로 만들면 용의자들이 전부 밋밋해진다.

**둘. 다섯 명 전원이 숨은 범죄에 연루되는가.**
주범 1, 협박당한 자 1, 추적자 2~3. 각자 감출 것이 있어야 전원이 수상해 보인다.

**셋. 트릭에 허점이 있는가.**
"자살할 사람이 왜 손님을 불렀나" 같은 것. 없으면 파고들 지점이 없다.

**넷. 범인이 가장 안 수상해 보이는가.**
동기가 제일 선명한 사람이 범인이면 5분 만에 끝난다.

넷 중 하나라도 비면 템플릿으로 넘어가지 않는다. 스케치 단계에서 버리는 게 훨씬 싸다.

### 스케치 예시 · 산장 살인사건

```
무대       : 외딴 산장, 겨울
피해자     : 윤다인(30), 소설가. 산장 장기 투숙
숨은 범죄  : 마약 유통망. 피해자가 공범
범인       : 산장지기 (역할: 주범. 유통 총책이자 가명의 주인)
트릭       : 위장 자살. 연탄 + 문틈 테이프 + 유서
트릭의 허점: 자살할 사람이 왜 그날 손님들을 초대했나
```

## 2단계 · 템플릿

`case-template.yaml`을 복사해서 채운다. **위에서 아래로 순서대로.**

순서를 지켜야 하는 이유:

```
숨은 범죄  →  동기가 여기서 나온다
살인      →  트릭이 물증을 결정한다
인물 배치  →  기회가 여기서 결정된다  ★ 가장 중요
물증      →  거짓말의 반박 근거
사실      →  검증기의 원자 단위
조사      →  탐색 공간
보고서     →  공란 = 진실 세계의 필드
산문      →  마지막. 사실이 다 확정된 뒤에
```

거꾸로 채우면 반드시 다시 쓴다. 산문을 먼저 쓰면 특히 그렇다.

---

## 작가가 쓰지 않는 것

**무고한 네 명의 진술은 직접 쓰지 않는다.**

`presence`(누가 언제 어디 있었는지)를 선언하면 엔진이 진술의 주장을 도출한다. 이것이 "무고한 사람은 거짓말하지 않는다"를 보장하는 유일한 방법이다.

손으로 쓰면 실수로 거짓이 섞이고, 그 순간 논리가 무너진다. 검증기도 그걸 잡아내지 못한다.

작가가 쓰는 것은 `voices` — 말투와 성격뿐이다.

## 핵심 원칙 세 개

### 판별자는 기회다

동기는 여러 명이 갖는다. 그게 레드 헤링이다.
**기회는 범인만 가져야 한다.** 나머지는 거리나 시각으로 배제한다.

산장 사건에서 나경·지안·리원 모두 동기가 있었지만 셋 다 아침 도착이었다.

### 무료 공개는 탐색을 줄이고 추론을 줄이지 않는다

장을 확인하면 정보가 공개된다. 허용되는 것:

- 사망 추정 시각 축소
- 새 조사 대상 공개
- 흉기 후보 좁히기
- 용의자의 추가 진술

**추가 진술은 자기 비밀을 말하지 않는다.** 남에 대해서, 또는 사건 전반에 대해서만. 자기 비밀은 조사로만 나온다.

### 어휘는 고정, 구성은 가변

공란 라벨은 고정 어휘에서만 고른다. 그래야 생성기가 돌고 번역이 싸다.

**장의 개수와 구성은 사건마다 달라야 한다.** 모든 사건이 5장이고 4장이 항상 `감춰진 사건`이면, 플레이어가 첫 화면에서 반전을 예측한다.

## 검증

```
tsx src/cli.ts --case my-case.yaml
```

검증기가 자동으로 확인하는 것:

- 유죄가 성립하는 인물이 정확히 한 명인가
- 거짓말이 전부 반박되는가
- 핵심 사실의 획득 경로가 2개 이상인가
- 각 장이 그 시점의 가용 정보로 확정 가능한가
- 최단 경로 · 기대 경로 · 난이도

**통과 후 볼 것: `기대 경로 + 1 ≤ 예산`**

여유가 0이면 한 번의 헛발질로 클리어 불가가 된다. 그 긴장이 의도라면 `hard`로 두고 캠페인 후반에 배치한다.

## 규모 기준

> ★ **용의자는 언제나 5명이다** ★ 규모가 바뀌어도 이 칸만은 안 바뀐다.
> `SYSTEM-DECISIONS.md` §3 (2026-07-29 개정 — 옛 3~7명 사다리는 폐기됐다).

| | 용의자 | 장 | 공란 | 예산 | 조사 | 소요 |
|---|---|---|---|---|---|---|
| daily | **5** | 2 | 7 | 6~8 | 25 | 20~25분 |
| campaign | **5** | 5 | 16~19 | 5~6 | 20+ | 45~60분 |

**예산은 규모에 비례하지 않는다.** 5명이면 장이 둘이든 다섯이든 기대 경로가 6
근처다 — 밀어 올리는 것은 장 수가 아니라 **무고한 넷 전원에게 주는 레드 헤링**이다.
daily 가 campaign 보다 예산이 큰 것은 오류가 아니다.

**생성기는 daily 규모만 담당한다.** campaign 규모를 자동 생성하려 하면 검증 실패율이 급등하고 서사가 무너진다. campaign은 사람이 쓴다.

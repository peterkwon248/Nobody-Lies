# Deposition · 데포지션 — 추리 게임 (프로젝트 인계 노트)

정지된 살인 사건 하나(산장 살인사건)를 플레이어(무명의 수사관)가 진술·조사·보고서로 푸는 추리 게임.
계보: Return of the Obra Dinn → The Case of the Golden Idol. 사건은 논리 검증기를 통과해 자동 생성됨(이 데모는 산장 사건 1개).
**마스터 스펙 = 사용자가 붙여넣는 `design-brief.md`** (이 저장소엔 파일로 없음). 항상 그 문서 기준으로 판단.

## 파일 맵
- **`추리게임.dc.html`** — 메인 게임(단일 DC). 거의 모든 화면·로직이 여기 있음.
- `추리판.dc.html` — 상황판(화이트보드형 추리 캔버스) 자식 DC. 게임의 `board`/상황판 뷰에 seed prop으로 마운트됨.
- `추리판미리보기.dc.html` — 상황판 실험용 미리보기(본편과 별개). 상황판 기능은 여기서 먼저 실험 후 `추리판.dc.html`에 이식해 옴.
- `*비교.dc.html`, `*미리보기.dc.html` — 과거 브레인스토밍용 옵션 비교 스크랩. 산출물 아님.
- Vector DS: `_ds/vector-design-system-490b734e-7df2-4af7-b176-9c91211b1ef6/`. 모든 DC의 `<helmet>`에서 `_ds_bundle.js`+css 로드, `<x-import component-from-global-scope="VectorDesignSystem_490b73.*">`로 마운트. 새 토큰 만들지 말고 `var(--*)` 사용. 다크 우선. 사이드바 패널 토글은 DS의 `PanelIcon`(둥근 사각형+레일) 사용 — Lucide 아이콘 아님.

## 핵심 게임 모델 (건드릴 때 반드시 지킬 것)
- **게임이 플레이어 대신 추리하지 않는다.** 자동 모순감지·게임의 텍스트 강조·조사 추천·오답 개별 지목 전부 금지. (과거 3번 정답 누설 사고 → 전부 이 원칙 위반이었음)
- **일회성 노출은 버그.** 공개된 텍스트/정보는 영구 재접근 가능해야 함(토스트는 "어디 생겼다" 신호만).
- **보고서 판정(현재 모델, A블록에서 재편 완료):**
  - 항 상태 = 미완성 / 완성 2종. `항 확인` 버튼 없음 — 공란 다 채우면 자동 `완성`, `비우기`로 되돌림. 잠금 없음(모든 항 처음부터 열람·입력).
  - 실시간 채점 없음(오답에 침묵). 되돌릴 수 없는 건 **최종 제출** 하나뿐 → 제출 후 채점. 제출 다이얼로그에 미채움 공란 개수 경고.
  - 정보 공개 트리거 = 항 **완성**(정답 여부 무관). `computeReveals(blanks)`가 감지 → `state.solved`(sticky) 세팅 + `state.unread`/`toast` + invLog seal 기록.
- **정보 층위 3종:** 확정(브리핑·확보물증, 실선·채움)/주장(진술, 따옴표·기울임·인물색)/판단(공란, 입력필드). 모순 판정은 확정 층 기준만.
- **조사:** 별도 화면 없음(사이드바에 '조사' 항목 없음). 공간→현장 평면도 클릭, 인물→용의자 카드 버튼, 관계→관계 그래프에서 두 노드 선택. 잔여 조사 예산은 하단바 상시. 조사 기록은 평면도·그래프에도 누적.
- **관계 그래프:** 빈 상태 시작(추측 간선 안 그림). 조사/항 완성으로만 간선 등장. 두 용의자 노드 선택 → 알리바이 대조 실행.
- **레드 헤링을 시각적으로 구분 금지**(결정적 단서 vs 무고한 비밀). 프로필 카드에 유죄 판정(O/X·유력) 금지 — 사실만.
- **인물 색**은 전 화면 동일(진술 레일·격자·프로필·평면도 점·메모·상황판). 초상화 없음(v1은 색). 실존 인물명은 디자인 단계 임시.

## 화면 (추리게임.dc.html 내 view)
홈 → 사건 상세 → 플레이(프롤로그 → 브리핑 → 진술 정독(순차, 건너뛰기 가능) → 자유 진행).
사이드바: 사건 개요 / 보고서(서술·목록·보드 3모드) / 진술(구조 격자·원문) / 용의자 프로필 / 현장 평면도(시간 스크럽) / 관계 그래프 / 상황판 / 조사 기록 / 메모 / 표기 안내(상태 레퍼런스=핸드오프 문서). 우측 디테일 패널(탭)로 교차참조. 좌우 사이드바 토글·집중 모드. 모바일=하단 탭+더보기. KO/EN·다크/라이트 전부 지원.

## 작업 방식(사용자 선호)
- 간결·직접. 큰 결정은 먼저 브레인스토밍하고 승인받은 뒤 구현. "미리보기로 보여줘" 하면 옵션을 실제로 만들어 비교시켜 줌.
- 상황판 같은 복잡 기능은 `추리판미리보기.dc.html`에서 실험 → 승인 후 `추리판.dc.html`(+본편)에 이식.
- 로직은 `dc_js_str_replace`(핫리로드), 템플릿은 `dc_html_str_replace`. 큰 배치는 `str_replace_edit` edits 배열.
- 끝나면 `ready_for_verification`. 큰 변경은 검증기 포크, 사소하면 skip.

## 신규 정보 provenance (일회성 노출 원칙 구현)
새로 공개된 정보는 두 층위로 표시: (1) 도착 신호 = 토스트("어디 생겼다") + 사이드바 안 읽음 점(방문 시 소거, `state.unread`), (2) **영구 provenance 라벨** — 그 자리에 "N항 완성으로 공개/갱신" 배지가 계속 남음(진술의 `추가 진술` 라벨과 동일 방식). 진술뿐 아니라 사건 개요(사망추정 시각 축소 시 갱신 배지+이전 범위 취소선)·현장 평면도(후공개 공간에 공개 칩)에도 적용됨. 새 화면/정보를 추가할 때 이 두 층위를 반드시 함께 붙일 것.

세션을 닫는다. **커밋되지 않은 것은 다음 기계에서 존재하지 않는다.**

## 1. 게이트 — 여기가 커밋 게이트다

```bash
npm run build
```

**exit 0 이 아니면 커밋하지 않는다.** 실패 내용을 보고하고 멈춘다. 고칠 수 있으면
고치고 다시 돌린다. 초록을 못 만들면 그 사실을 워크로그 Blockers 에 적고 **커밋은
사람에게 묻는다.**

## 2. 인계 파일 넷을 **같이** 갱신한다

하나라도 빠지면 다음 기계가 속는다.

> ⛔ **워크로그 누락은 이 저장소의 재발 실수다 — 이제 세 번이다.**
> `6f6dccb` · `94f25c1` · `a59e413`. **뒤의 둘은 이 경고문이 이 자리에 있는 채로
> 연속으로 났다** — 아래 표도, 「하나라도 빠지면」도 이미 적혀 있었다.
> **그러니 목록과 경고로는 못 막는다는 것이 실측됐다.** §2-b 의 검사가 그래서 있다.
>
> 실제 피해: `a59e413` 시점에 `latest.md` 가 **두 세션 낡아** 있었고, 내용이
> 「⑤검열관 첫 실행」에 멈춰 상황판 삭제·감사 20건·수리-A 가 통째로 없었다.
> 닫힌 일(`PLAYTEST.md` 신설)이 **열린 채**로 남아 다음 세션에 그대로 전달됐다
> (2026-08-06 `before-work` 가 잡았다).

| 파일 | 방식 |
|---|---|
| `docs/MEMORY.md` | 정본. 이번 세션이 만든 규칙·발견을 절로 넣는다. **닫힌 절은 지우지 않고 ✅·⛔·⏭ 를 박는다** — 지우면 그날 무엇이 남아 있었는지가 사라진다 |
| `docs/NEXT-ACTION.md` | §다음 즉시 액션을 **하나로** 갱신. 머리말의 마지막 갱신·브랜치·기계 줄도 |
| `docs/SESSION-LOG.md` | append-only, **최신이 위**. 날짜 + 기계명 헤딩 |
| `.omc/worklog/latest.md` | 덮어쓰기 (최신 1개만 산다) |

`.omc/worklog/latest.md` 서식은 유지한다:

```
---
session_date · project · working_directory · machine
---
## Completed Work   (무엇을 닫았나 · 항목별 · 검증한 것)
## In Progress
## Remaining Tasks   (- [ ] 체크박스. 🎯 로 다음 하나를 표시)
## Blockers / Issues (⚠️)
## Notes for Next Session
## Files Modified
```

> ⛔ **파일의 추적 상태를 「미추적」이라고 적지 마라 — 「이 커밋에 포함됨」으로 적는다.**
> **워크로그를 쓴 뒤에 커밋하므로**(§2 → §3), 이 커밋이 쓸어 담을 파일은 **집필 시점에
> 언제나 미추적으로 보인다.** 그대로 적으면 다음 세션이 `git add` 를 하거나 「트리 깨끗」을
> 거짓으로 읽는다 — **읽기 오류가 아니라 잘못된 조작이다.** 2026-08-04에 실제로 났다
> (`solve-check.ts` · `6d2e660` — 워크로그 세 곳이 「미추적」이었고 다음 세션의
> `before-work` 가 잡았다). **커밋이 안 바꾸는 사실**(게이트 미배선 · 미완 · 블로커)은
> 그대로 적는다 — 지우라는 말이 아니라 **추적 상태와 배선 상태를 섞지 말라는 말이다.**

**닫힌 것을 열린 채로 남기지 않는다.** 갱신하면서 낡은 줄이 보이면 그것도 같이 고치고,
무엇이 낡았었는지를 커밋 본문에 적는다.

## 2-b. 넷이 다 손에 잡혔는지 **센다** — 여기가 인계 게이트다

```bash
git status --short docs/MEMORY.md docs/NEXT-ACTION.md docs/SESSION-LOG.md .omc/worklog/latest.md
```

**네 줄이 나와야 한다.** 세 줄 이하면 **빠진 파일이 있다는 뜻이고, 그 상태로 닫지 않는다.**
빠진 것을 갱신하고 다시 센다.

> ★ **왜 「고쳤나」가 아니라 「센다」인가** — 두 번의 누락 다 *고칠 생각이 없어서*가
> 아니라 **다 고쳤다고 믿어서** 났다. 믿음은 셀 수 없고 `git status` 는 셀 수 있다.
> 게이트(§1)가 코드에 대해 하는 일을 이 줄이 인계 파일에 대해 한다.
>
> ⛳ **넷 중 셋만 바뀌는 「정상」 세션은 없다.** 커밋할 것이 있으면 `SESSION-LOG` 는
> 무조건 늘고, `latest.md` 는 덮어쓰기라 무조건 바뀐다. **면제 사유가 있다고 느끼면
> 그것이 곧 예전에 빠뜨린 이유다** — 면제 대신 「이번 세션은 X 였다」를 파일에 적는다.

## 3. main 에 커밋한다

feature 브랜치·PR 없다. 직접 `main`.

- 산출물은 커밋하지 않는다 — `app/public/cases/` 는 `.gitignore` 에 있고 `dev`·`build`
  둘 다 앞에서 굽는다
- `package-lock.json` 에 `"peer": true` 표시만 지운 차분이 있으면 **되돌린다**
  (npm 버전 차이지 의존성 변화가 아니다)

커밋 메시지는 **한국어**. 제목은 무엇이 바뀌었는지 한 줄(인계 커밋이면 `after-work: ` 접두),
본문은 **왜 그렇게 했는지**와 낡아서 고친 것. 끝에:

```
Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
```

$ARGUMENTS 가 있으면 제목에 반영한다.

## 4. 푸시하고 확인한다

```
git push && git status && git log --oneline -3
```

그리고 **넷이 정말 이번 커밋에 들어갔는지**를 커밋 쪽에서 한 번 더 센다 —
§2-b 는 커밋 전이라 「고쳤는데 `git add` 가 안 됐다」를 못 잡는다:

```bash
for f in docs/MEMORY.md docs/NEXT-ACTION.md docs/SESSION-LOG.md .omc/worklog/latest.md; do printf '%-28s ' "$f"; git log -1 --format='%ad  %h  %s' --date=short -- "$f"; done
```

**넷의 커밋 해시가 전부 같아야 한다 — 이번 세션의 인계 커밋 하나로.**
하나라도 다른 해시를 가리키면 **그 파일은 이번 세션에 안 들어갔다** —
세션을 닫지 말고 그것부터 채워 커밋한다.

> ⛔ **날짜로 세면 안 된다 — 재보고 고쳤다 (2026-08-06).** 이 검사를 처음 쓸 때
> *"넷 다 오늘 날짜여야 한다"* 로 적었는데, **실제 누락 사례에 걸어보니 통과했다:**
> ```
> docs/MEMORY.md          2026-08-05  a59e413
> docs/NEXT-ACTION.md     2026-08-05  a59e413
> docs/SESSION-LOG.md     2026-08-05  a59e413
> .omc/worklog/latest.md  2026-08-05  b1bd6d0   ← 두 세션 전인데 날짜가 같다
> ```
> **하루에 세션이 셋 돈 날이라 낡은 것도 「오늘」이었다.** 이 저장소는 같은 날
> 여러 세션이 흔하다(`NEXT-ACTION` §날짜 대응표가 그 이력이다).
> **가르는 것은 날짜가 아니라 해시다.**
>
> ★ **이 검사가 `a59e413` 을 잡았을 검사다.** 그날 넷 중 셋만 갱신됐는데 화면에는
> **「푸시 성공 · 트리 깨끗」**만 떴다. **누락은 초록과 구별되지 않는다.**

작업 트리가 깨끗한지 확인하고, **다음 세션이 `before-work` 로 무엇을 읽게 되는지**를
한 문단으로 보고한다.
